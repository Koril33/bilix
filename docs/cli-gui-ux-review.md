### 3.1 A-02：信息与按视频选集

- 展示标题/UP 主/时长、实际可获取画质/编码、音轨、选集。现有模型没有封面字段，封面非 A 门槛。复制信息 JSON 是辅助动作，不是默认视图。
- 每个来源独立保存选择：未设置遵循 URL 的 ?p=，否则默认全部；显式选择优先。UGC/PGC 都复用 select_pages/discover，不复制番剧/电影解析。
- 可保留“应用同组选集规则到全部地址”，但必须明确点击。空选择阻止该来源加入下载，不能误当“全部”。
- 来源显示读取中/成功/失败及重读入口；异步结果按来源 ID 和编辑代次匹配，迟到数据不得写到已改地址的卡片。
- 首 P 的流不能证明其他 P 可用；未读取 P 标“执行前确认”。宣传画质与实际可获取流分开；不可获取不自动等于需要会员，未知原因不给虚假结论。
- 试看/DRM 沿用拒绝策略。地址/选集改变后丢弃对应预览；账号变化后不复用未经验证的播放结果；临时 URL 过期时重新解析。

### 3.2 A-03：会话记录与重试

- 保留窗口内不同批次及每项结果。A 仍串行，活动期间不启动新批次/重试或第二 worker；按钮禁用并解释。**保留记录不等于运行中追加。**
- 预览在独立区域，不作为执行历史；重预览/失败不清下载记录。点击开始才创建执行批次与尝试。
- 筛选为全部、待处理、活动、已完成/跳过、失败、取消。只改变视图，按 task_id 操作，不按行号。
- 默认“按原设置重试所选项”：原设置是被选失败/取消尝试的快照。上一轮明确用过当前设置，下一轮默认用上一轮快照，不是最早一轮或当前表单。
- 另设“按当前设置重试所选项”，显示数量、目录、画质/音轨、strict/覆盖摘要。不同原设置的批量重试逐项复用，不合成同一 DownloadOptions。
- 仅重试所选选集，保留成功/跳过项和旧尝试。批量失败项与取消项分别操作，不能把取消项暗中纳入“全部失败”。重试是重新执行，不是续传。
- 尚未发现媒体的来源失败提供“按原设置重新读取”，创建新来源请求并关联旧 request_id，保留旧失败记录；不伪造 task_id 或 P。批量失败操作若同时包含来源和媒体，先分别列出请求数/媒体数，再按各自快照执行。
- 默认表格展示每任务最新尝试，详情可查看旧尝试；历史批次汇总保持当时的失败/成功数量，后续重试成功不能把旧批次改成成功。重试结果归本次重试批次。
- 提供打开文件/所在目录/复制路径。先检查存在性；计划路径不冒充完成文件，跳过明确“已有文件，未校验”。
- 清除已完成/跳过记录只清记录；失败/取消用独立动作。清记录不删除输出或临时材料，禁止含混的同时删除文件“移除”。
- A 的清记录动作仅空闲时可用；活动期间可筛选和查看已有输出，但不能启动重试或删除记录。清记录不改写已结束批次汇总。
- 不保留跨重启历史。活动关闭提示停止本批、保留完成文件、关闭后会话记录不保存，并允许返回继续；空闲关闭不确认。退出等待 worker/FFmpeg 结束。

### 3.3 A-04：冲突预览

两端复用纯计算/只读查询入口，展示实际媒体、目标、降级警告及预测：

| 预测 | 当前判定 | 解释 |
| --- | --- | --- |
| new | 目标不存在 | 预计新下载 |
| skip | 是文件，未允许覆盖 | 预计跳过，旧文件未校验 |
| replace | 是文件，允许覆盖 | 预计新文件校验后替换 |
| blocked | 目标存在而非普通文件，或规划失败 | 当前不能执行，安全原因 |

沿用 execute 的 exists/is_file 规则；预览不创建目录、写探测文件、检查媒体或清临时目录。权限/空间/网络在执行时检查，“不存在”不等于保证可写。

预测是时点估计，执行和提交再次检查。预览后新增同名文件默认仍不覆盖。同批同路径给重复目标警告，后项结果受前项成功/失败影响，不静默去重。

GUI 显式覆盖后使用常驻摘要，不每个文件重复确认；CLI --overwrite 保持无人值守。统计区分来源、发现选集和规划失败，不将一地址等同一媒体。

### 3.4 A-05–08：首屏、配置、账号、CLI

首屏保留地址、目录、画质与预览/开始；更多选项收纳编码、音轨、strict、覆盖和批量选集。非默认项折叠时仍在常驻摘要。解释实际结果；默认 AAC 不改 best，strict 仍同时约束指定画质/编码。

配置读取返回文件值、有效默认、来源及变量名。优先级为任务/CLI 显式覆盖 > 对应环境变量 > TOML > 默认。任务覆盖不修改配置。设置页编辑文件值，保存后重读有效默认，准确提示已写文件但当前由环境控制。

下载页显式改过目录时不被保存默认覆盖；没改过时采用重新加载的有效默认，而非 save_settings 返回的未叠加环境文件值。FFmpeg 同样区分来源。保存检查类型/路径形态，可运行性由显式诊断验证，不声称未执行路径可用。

启动离线显示未保存/已保存未核验/无法读取。文件存在或可解析不等于登录有效；查询后区分有效、失效和网络失败。启动零账号请求，不输出 Cookie。

按钮按操作显示取消本批下载/信息查询/登录/诊断。A 下载取消仍结束活动及未执行项，不是暂停或单项取消。立即反馈正在停止，等待协作取消，不能承诺请求瞬间退出。

CLI 增加登录、info、dry-run、目录、多 P/批量例子，按基本下载/选集媒体/高级行为分组。使用 Typer 的公开 rich_help_panel、help/epilog，完整框架汉化非 A 要求。[Typer 帮助接口](https://typer.tiangolo.com/tutorial/commands/help/)

保留两个命令名、模块/URL/BV 旧入口、video/user/--info/--origin/-o 的原含义与补全。示例推荐规范命令；恢复建议从稳定类别/动作生成，不解析异常字符串，DRM 不建议重试解决。

现有 info/auth status 的 --json 保持字段含义和根容器结构，不因任务重构改成 JSONL 或重包一层。download 默认人类输出、quiet 和非 TTY 行为保持兼容；新的机器协议只能显式选择。帮助/示例中新增参数必须与实际冻结功能一致。

## 4. A-01：最小任务与内部事件契约

### 4.1 对象、归属与快照

把纯 Python 模型移出 Qt 依赖；可用 tasks.py/events.py/runner.py 或现有合适模块，文件名非公开 API。共享编排逐步迁移，两端只适配，不要求先拆全部窗口。

| 对象 | 最小职责 |
| --- | --- |
| 来源请求 | request_id、规范地址、选集规则、请求选项快照、读取状态；可发现零个或多个任务，重新读取关联原 request_id |
| 批次 | batch_id、本次请求/尝试、发现是否完成、取消/汇总；重试批次可引用既有任务 |
| 媒体任务 | 稳定 task_id、来源引用、稳定选集标识、标题、尝试列表 |
| 尝试 | attempt_id 或单任务递增编号、本次 batch_id、快照、状态/结果/安全错误 |
| 快照 | 选集、quality/codec/audio、strict/overwrite、绝对目录、有效 FFmpeg 配置偏好 |
| 预览 | 独立 preview_id、来源/选项/账号代次、预测；不作为任务终态 |

task_id 是不透明唯一值，不用行号/标题/URL/P 序号替代。显式保存选集关系，不再从 P1 标题正则反推。相同 URL 输入仍不同来源，不静默合并；同任务重试 ID 不变，尝试递增。

快照固定要求，不固定实际流。重试重新核验凭据/权限并解析短期 URL；原要求也可能产生不同降级结果，本次记录实际选择和警告，不把旧信息当授权。

已经发现的 UGC 媒体记录 BV/CID，PGC 记录 episode_id 等可获得身份。重试时校验身份，不仅相信原 P 序号；内容删除、选集重排或身份变化时阻止原任务自动下载其他内容，提示重新选择并创建新任务。发现失败、尚无媒体身份的来源只能重新读取，不能声称已经锁定原媒体。文件名仍由本次实际计划生成，标题/媒体选择变化导致输出变化时显示新路径，不暗中使用旧路径覆盖。

快照不存凭据/CDN。ffmpeg=None 表示自动查找；保留已有文件跳过不需 FFmpeg 的行为，首次需要媒体处理时解析程序并记入尝试诊断。执行不重读表单/新默认，重试的账号权限则必须刷新。

### 4.2 状态与终态

来源：queued → loading → discovered | failed | canceled。发现失败归请求，界面可重读，不能伪造 P，也不能从汇总漏掉。

媒体正常路径：

```text
queued → loading → downloading → checking_video → checking_audio
       → muxing → committing → completed
```

failed/canceled 是任一未终结阶段的终态；skipped 是执行前已有文件或非覆盖提交竞争的终态。planned 只用于预览。cancel_requested 是控制标志，尚在清理不能提前宣布已取消。

每尝试只一个终态；runner 归一服务阶段与返回结果。已提交后取消不改写成功；提交失败不先报完成。重试新尝试、旧尝试只读。旧尝试/旧序号/重复事件不能改写当前尝试，未来尝试及非法转移拒绝。

### 4.3 内部事件、错误与汇总

内部事件含类型、batch/request/task/attempt 归属、尝试内单调序号及适用 stage/progress/result/error。采样用 monotonic，墙钟只记录日期。锁外回调，Qt 模型只在主线程更新。[Qt 模型线程要求](https://doc.qt.io/qt-6.11/qabstractitemmodel.html)

内部传安全信息 DTO/public_dict，公开协议只用白名单。登录二维码走独立内存通道，不进入可记录/导出的下载 sink。

汇总区分请求总数及失败/取消、已发现任务数、各尝试终态、发现是否完成和批次取消。未知总量显示已发现 N、仍在读取，不猜。无媒体任务的来源失败也令整批失败。

CLI 成功/跳过/成功预览为 0，业务/来源失败为 1，参数解析失败为 2，用户中断完成受保护取消为 130。中断优先 130，仍保留已有结果；强制杀死/断电不保证 summary。

增加内部 error_code/安全动作，不把 APIError.code 的上游数值当项目类别。按类型/显式字段传递；DownloadError 包装保留类别，不分析中文字符串。

类别至少含输入/配置、来源不存在、需登录/过期、权限、试看/DRM、媒体选择、网络、文件系统、FFmpeg、校验、合并、未知内部失败。动作可为登录/调选择/查目录/诊断/稍后重试，可重试不等于自动重试。A 固定内部语义，B 才冻结公开字符串协议。

本地结果/失败临时目录可用于界面提示；禁止 headers/响应正文/Cookie/token/二维码 key/签名 URL/异常局部变量。第三方未知异常仍为通用安全消息。

### 5.1 队列与取消

网页客户端和 execute/transfer/media 都使用当前任务作用域，不能只给传输换 token。控制器区分队列/批次控制与任务 token，网络不在队列锁内。

“停止队列”定义为停止调度后续项；显式“停止并取消当前项”才结束当前项，其余保留 queued 可再启动。“取消所选项”才令所选待处理/活动项取消。禁止把 A 整批取消改按钮名字伪装成任务取消。B 的移除也不删除已输出文件。

### 5.2 速度与 ETA

在共享纯 Python 层计算，Rich/Qt/JSONL 适配同值。每流事件含名称、流尝试编号、字节、可选总量、monotonic 时刻；HTTP 内部重试与用户重试分开。流尝试变化/计数回退重置窗口，样本不足不显示速率/ETA；未知任一路总量时 ETA 为 null。

传输结束展示校验/合并。剩余字节不包括这些阶段，不称整项/整批 ETA。1.7.2 必须交付满足上述语义的速度、传输 ETA 与批次计数；仅完成速度或阶段提示只能算阶段性实现，不能作为 B-02 完成。整体估时需要另做阶段测量，不是本次承诺。[进度与阶段参考](https://developer.gnome.org/hig/patterns/feedback/progress-bars.html)

### 5.3 config、stdin、诊断与偏好

config 保留裸命令查看入口。新增操作只编辑允许的业务键；reset KEY 删除该键文件设置，环境/默认决定有效值，不承诺清环境。失败保留旧文件，单键更新不丢其他键值；注释/格式保留策略单独说明。语法/类型校验与 FFmpeg 实际诊断分开。不得删除凭据/下载。

stdin 仅显式 --file -，不自动消费管道。UTF-8/BOM/空行/行首 # 与文件输入一致，保留行号/顺序/重复，不自动去重。位置参数先、列表后，只读 stdin 一次。非法地址逐项记录失败并继续合法来源；整个输入无法解码/读取时在执行前失败。帮助写明交互 EOF，参数错误与业务失败退出码仍区分。

诊断默认只导出产品/Python/Qt/FFmpeg 版本、安全状态/类别和已选统计，省略完整路径/用户名/账号/标题/源地址/环境全集/原始配置/令牌。确需路径时用户在导出预览明确选择；不要把 JSONL 本地结果路径白名单照搬公开诊断。清临时目录/校验旧文件另列未来需求，不捆绑导出。

偏好可用 QSettings；业务默认仍 config.toml。独立版本/回退，不暗中授权覆盖，恢复后的危险选项仍常驻摘要。基本 Tab/焦点/标签/主动作按键归 A，额外偏好/快捷键才归 B。

## 6. B-03：JSONL 草案与兼容

**当前命令不支持 --jsonl。** 本节是拟定协议，正式实现先补契约测试，不自动序列化内部对象所有字段。

每行 UTF-8 JSON，含 schema_version: 1、event、batch_id。stdout 仅协议；提示/诊断 stderr，禁用 stdout Rich/颜色。正常结束一次 summary；参数解析失败可 stderr/退出 2，不伪造批次。管道写失败停止操作并安全退出，不无限继续下载。

| 事件 | 最小允许字段（除公共字段） |
| --- | --- |
| source | request_id、规范地址、来源位置、发现状态，失败则 safe error |
| task | request_id、task_id、attempt_id、sequence、选集、非终态状态/阶段 |
| plan | task_id/attempt_id、目标、实际媒体、冲突预测、警告 |
| progress | task_id/attempt_id、sequence、流尝试、字节/总量、speed_bps、transfer_eta_seconds |
| result | task_id/attempt_id、sequence、终态、输出或 error_code/message/action |
| summary | 请求/任务计数、discovery_complete、cancel_requested、对应退出码 |

result 是唯一终态事件，task/stage 不再重复终态。路径是用户请求的本地结果，可在该协议返回；公开诊断默认省略。地址规范化后输出，不包含任意查询参数。未知用 null，单位 bytes、bytes/s、seconds，不本地化数值。

error_code/action 固定词汇与含义，上游数值可单独字段，不是完整响应。新增可选字段/事件有忽略策略，同 schema 不改类型/单位/含义；破坏性修改增 schema，不借产品 patch 偷改。

部分失败逐项 result、正确 summary、退出 1；中断 130 保留既有结果；来源失败不能漏。dry-run 只出 plan/summary，不假称下载完成。限频不丢终态/最后字节。用同一 runner 和合成响应比较两端计划、终态、计数。公开 code 拼写在实现 B-03 前以契约测试冻结，A 的内部类别不冒充已经发布的协议。
