# BiliX 1.7.4 GUI 优化方案 A：列表为主，新建下载走对话框

> 历史设计/评审：保留当版基线、建议和决策。当前行为见 [使用文档](README.md#当前使用与开发)，未完成功能见 [backlog.md](backlog.md)，缺陷与流程问题见 [workflow-issues.md](workflow-issues.md)。构建、测试与发布从 [handoff.md](handoff.md) 进入，不直接执行下方旧版命令。

> 更新日期：2026-10-10。基于已发布 1.7.3 的 `gui/` 代码与截图。状态：1.7.4 开发依据；实际实现、验收及发布状态见 [本版记录](validation-1.7.4.md)。
> 本轮已统一范围与交互；链接自动解析、有 token 时自动验证账号、最小化到托盘及完成通知均为 1.7.4 必做项。本文保留设计约束，不把设计验收条目等同于实际全部通过。

## 1. 背景与问题

### 1.1 现状

当前主窗口是一张自上而下的"大表单"：顶栏 → 链接输入 → 保存路径 → 画质与按钮 → 下载列表 → 底部状态行。

### 1.2 核心问题

| # | 问题 | 影响 |
|---|------|------|
| 1 | 表单占据上半屏，下载列表被挤到下面 | 一次下载只用一次表单，其余时间表单都在占空间；列表为空时窗口大半是空白 |
| 2 | 下载已有强调色，但其他表单控件仍密集排列 | 主操作与准备操作缺乏统一层级 |
| 3 | 账号、设置与表单控制混在主界面 | 导入、诊断在 1.7.3 已部分收起，仍可进一步整理入口 |
| 4 | 底部"状态栏"实际是一行布局，空闲时显示的是使用说明而非状态 | 信息位置不对，价值低 |
| 5 | 系统控件外观与局部手写样式并存，高度、间距不统一 | 视觉缺乏一致性 |
| 6 | "解析 → 选选集 → 下载"流程被拆在三个位置（主窗口、选集对话框、选项对话框） | 流程断裂，需要来回切换 |

### 1.3 目标

1. 主窗口以**任务列表**为中心，与 IDM、Motrix、qBittorrent 等同类软件的心智模型一致。
2. 把"新建下载"收敛为**单一入口 + 单一对话框**，一次性完成：粘贴 → 识别 → 选集 → 下载。
3. 低频功能进入**菜单栏**；常驻信息进入**真正的状态栏**。
4. 建立统一的视觉规范（颜色、间距、字号、图标），支持浅色 / 深色。
5. 不改动下载引擎（`service` / `tasks` / `planner` / `media` 等），仅重构 GUI 层。
6. 链接输入自动解析；启动发现本地 token 后自动查询账号有效性、昵称与会员状态，无需先手动点“查询状态”。
7. 支持最小化到托盘与下载批次结束通知，保证主窗口可恢复、有明确退出入口。

### 1.4 非目标

- 不更换 GUI 框架（继续使用 PySide6 / Qt Widgets）。
- 不引入第三方 UI 组件库（避免许可证与依赖风险；如日后想做 Fluent 风格再单独评估）。
- 保留任务身份、尝试快照与历史模型主结构；允许在 GUI 展示模型中增加进度数值角色、图标与计数辅助数据。
- 不加入运行中追加下载、单项取消、任意选中项移除、暂停续传、媒体并发或限速。非模态对话框只允许在忙碌期间准备草稿，不等于支持追加任务。
- 不加入跨重启下载历史或草稿持久化；仅保存明确列出的 GUI 偏好。

## 2. 设计原则

1. **列表是主角**：尽量把主窗口面积留给列表；80% 为默认尺寸下的视觉目标，不作为所有小窗口的硬性比例。
2. **主操作唯一**：每个界面只有一个强调色按钮。
3. **低频藏起来，高频放外面**：新建下载、重试、清除在工具栏；设置、账号在菜单；取消仅在状态栏提供一处，明确作用对象。
4. **状态要可见**：登录状态、队列概况、当前操作进度一眼可得。
5. **默认值替用户做决定**：画质、保存目录、音频格式默认可用，用户只在需要时才展开选项。
6. **跟随系统**：通用颜色取自调色板，品牌与语义颜色集中配置；支持系统浅深色及运行时变化，不在控件中散写色值。
7. **自动但不代替用户提交**：解析、账号验证自动执行；下载、重试、覆盖和退出仍由用户明确触发。

```
├─────────────────────────────────────────────────────────────┤
│  全部 12   进行中 2   完成/跳过 8   失败 1   已取消 1           │  筛选标签
├─────────────────────────────────────────────────────────────┤
│ ▸ 视频标题 A（多 P）            已结束 1 / 3                   │
│     P1 …                        已完成                         │
│     P2 …                        下载中        视频63% 音频31%  │
│     P3 …                        等待                         │
│ ▸ 视频标题 B                    已完成                         │  任务列表
│ ▸ 视频标题 C                    失败   登录已过期               │

├─────────────────────────────────────────────────────────────┤

```

### 3.2 空状态

列表为空时，不显示一行灰字，而是居中展示：

- 应用 Logo（半透明，较大）
- 一句话主文案："还没有下载任务"
- 一个主按钮："＋ 新建下载"；空状态时工具栏同名按钮使用次要样式，避免两个强调色按钮。
- 一行辅助文案："也可以直接把链接拖进来，或按 Ctrl+V 粘贴"

### 3.3 信息分布总览

| 位置 | 内容 | 频率 |
|------|------|------|
| 菜单栏 | 导入链接列表、登录 / 退出、设置、诊断、关于 | 低频 |
| 工具栏 | 新建下载、重试失败、清除完成/跳过、更多操作 | 高频 |
| 筛选标签 | 全部 / 进行中 / 完成与跳过 / 失败 / 已取消（带计数） | 高频 |
| 列表 | 任务与子任务、状态、进度 | 持续可见 |
| 状态栏 | 当前操作提示、队列摘要、登录状态、取消按钮 | 持续可见 |
| 新建下载对话框 | 链接、选集、保存位置、画质、高级选项 | 每次下载一次 |

## 5. 工具栏

### 5.1 按钮

| 按钮 | 样式 | 说明 |
|------|------|------|
| **＋ 新建下载** | 强调色，唯一的主按钮 | 打开新建下载对话框 |
| 重试失败 | 次要 | 空闲且存在最新失败任务或可重新读取的失败来源时启用；使用原参数 |
| 清除完成/跳过 | 次要 | 空闲且有可清除记录时启用，只清记录，不删文件 |
| 更多操作 ▾ | 次要 | 重试全部取消、清除失败/取消记录；选中项常用动作也可从此进入 |

取消不在工具栏重复出现。忙碌时“新建下载”仍可打开草稿，但草稿的自动解析、预览、下载会按第 7.6 节等待；重试及清除禁用。标题搜索框后置。

### 5.2 取舍说明

- 原来的两个菜单合并为“更多操作”，保留可发现、可由键盘到达的选中项入口，不把功能仅藏在右键或悬停中。
- 右键菜单复用相同动作；行内首期只提供一个“⋯”菜单按钮，对当前选中行常显，复杂悬停按钮组后置。
- “重试（原参数）”保留快照语义；原“按当前参数重试”改为“调整参数后重试…”，打开新建对话框的重试模式并确认参数。此模式固定选中的 task/request ID，不改变选集身份，也不读取另一份未提交草稿的半成品参数。

## 6. 任务列表

### 6.1 列设计

| 列 | 内容 | 宽度策略 |
|----|------|----------|
| 标题 | 视频 / 选集标题，带展开箭头；多 P 视频为父节点 | 自适应拉伸 |
| 状态 | 图标 + 状态文字；失败原因可省略显示，tooltip/详情提供全文 | 可调整宽度，有合理最小值 |
| 进度 | 视频/音频传输进度，或校验/合并/保存等阶段文字 | 可调整宽度 |
| 操作 | 选中行提供“⋯”菜单按钮 | 固定窄列，小窗口可由“更多操作”替代 |

### 6.2 状态的视觉表达

| 状态 | 表达 |
|------|------|
| 等待 | 灰色圆点 |
| 读取中 / 下载中 / 校验 / 合并 / 保存 | 主题色圆点或进度条 |
| 已完成 | 绿色对勾 |
| 已存在，跳过未校验 | 黄色提示图标（需要明确传达"未校验"） |
| 失败 | 红色叉，悬停显示原因 |
| 已取消 | 灰色横杠 |

> 颜色之外必须同时有**图标或文字差异**，不能只靠颜色（色弱友好）。

### 6.3 交互

- 双击行：完成/跳过项在文件存在时打开文件，其余任务打开详情；有子项的父行展开/收起。
- 右键菜单：打开文件、打开所在目录、复制路径、重试（原参数）、调整参数后重试…、详情…。没有任意移除或 Delete 删除入口。
- 多选：支持 Ctrl / Shift 多选与批量重试；仅失败/取消任务及尚未被重新读取的失败/取消来源可重试。分组父行不隐含选中其全部子任务；隐藏项不进入当前选中操作。
- 拖拽：支持把链接或 `.txt` 文件拖入窗口，触发新建下载对话框并预填内容。

### 6.4 进度与模型约束

- 继续使用 QTreeView / HistoryModel，保留稳定 ID、尝试编号与旧事件过滤。允许增加 GUI 数值角色，不从本地化进度文字反解析百分比。
- 用 QStyledItemDelegate 绘制进度和行内菜单；不为每行创建独立进度条与按钮，保持批量筛选合并刷新。
- 视频、音频分别显示传输进度；总量未知时显示已传字节或不定进度，不伪造百分比。需要紧凑展示时可用两条细进度条并标注流名称。
- 传输 100% 不代表任务完成，后续仍显示校验、合并、保存。父行只显示已结束/已发现数量，不虚构整体完成百分比。
- 未结束的发现阶段显示“正在读取 · 已发现 N 项”，不猜总数。只允许一个媒体任务执行，其音视频流可以沿用既有并行传输。

### 6.5 筛选标签与计数

用标签条代替原来的下拉框：

- 全部 · 进行中 · 完成/跳过 · 失败 · 已取消
- 每个标签显示计数，例如"失败 2"；计数为 0 时不隐藏标签，只显示灰色数字。
- “等待”并入“进行中”；已取消独立成标签，不当作失败。“完成/跳过”中仍明确区分已完成与“已存在，跳过未校验”。
- 计数按媒体任务最新尝试，加上尚未产生任务、尚未被关联重新读取的活动/失败/取消来源计算；分组父行不重复计数。已被重读的旧来源保留在详情/批次历史，不计入可重试来源数量。
- 标签计数与工具栏启用条件使用同一口径；刷新不丢终态，不在每次进度事件后重建全树。

## 7. 新建下载对话框（本方案的核心）

### 7.1 触发方式

- 工具栏"＋ 新建下载"、菜单 Ctrl+N。
- 空状态页的主按钮。
- 拖拽链接到窗口。
- 主窗口内按 Ctrl+V 且剪贴板含 B 站链接时，直接弹出并预填。

一个窗口会话只保留一份新建草稿。再次触发只聚焦已有对话框，不创建多个解析上下文；有未提交内容时不自动覆盖，导入/拖入新内容应明确选择追加或替换。

### 7.2 线框

```
┌─ 新建下载 ───────────────────────────────────────────┐
│                                                      │
│  链接 / BV 号                                         │
│  ┌────────────────────────────────────────────────┐ │
│  │ 粘贴 Bilibili 视频、番剧链接或 BV 号，每行一个   │ │
│  │                                                │ │
│  └────────────────────────────────────────────────┘ │
│                                                      │
│  ┌ 识别结果 ──────────────────────────────────────┐ │
│  │ ☑ 视频标题 A                        共 12 P     │ │
│  │    ☑ P1 …                           12:03      │ │
│  │    ☑ P2 …                           08:41      │ │
│  │ ☑ 视频标题 B                        1 P         │ │
│  │ 已选 13 / 14    [全选] [全不选] [反选]  范围 1,3-5│ │
│  └────────────────────────────────────────────────┘ │
│                                                      │
│  保存到   [ C:\Users\…\Downloads\djhx-bilix ] [选择…] │
│  画质     [ 最高可用 ▾ ]       ▸ 更多选项              │
│                                                      │
│  ───────────────────────────────────────────────────  │
│  文件预览                               [关闭] [下载]  │
└──────────────────────────────────────────────────────┘
```

### 7.3 分区说明

**A. 链接输入区**
- 多行输入框，最小高度约 3 行，可随对话框拉伸。
- 输入停止约 **500ms 后自动解析**，无需先点击解析；粘贴、导入、拖入均走同一流程。中文 IME 组合态期间不启动计时/解析，提交文字后再防抖。
- 解析中在输入区下方显示细进度条与"正在识别 2 / 3"；失败的链接在其下标红并给出原因，不阻塞其他链接。
- 本地逐行校验：不完整/不支持的地址仅标记对应行，合法行继续读取；注释、空行、BOM 与现有列表规则一致。保持来源顺序和重复输入，不擅自去重。
- 输入有改动立即使旧结果不可提交；自动解析调度、失败重试与过期响应规则见第 7.6、7.7 节。

**B. 识别结果区**
- 单 P 结果默认显示摘要；包含多 P 时自动展开选集列表，列表本身滚动，避免把对话框无限撑高。
- 树形选集列表展示复选框、标题与时长。
- 选集快捷操作：对当前视频全选 / 全不选 / 反选、输入范围后点击“应用”（沿用 `1,3,5-7` 语法），不因输入范围立即覆盖已有勾选；“应用到全部来源”需使用明确的独立动作。
- 保留普通多 P 链接默认全部、`?p=` 默认仅该 P 的规则，提示放在选集区。来源可以整体取消勾选；没有选中有效来源/选集时下载禁用。
- 选中某节点时可展开查看详情（原 `parts_info`）。

**C. 保存与画质**
- 保存目录默认取设置中的默认目录；本次修改只影响本次下载，不覆盖设置。
- 首次使用画质默认“最高可用”；之后可恢复第 11.3 节明确保存的上次画质，并显示当前选择。

**D. 更多选项（折叠区，默认收起）**
- 视频编码、音频格式、严格匹配、覆盖同名文件。
- 收起时在标题后用灰色小字显示非默认项摘要，例如"AVC · FLAC · 严格匹配"，与现在的 `option_summary` 作用一致。
- 覆盖同名文件不跨重启恢复，默认关闭；本次开启时在收起摘要与提交参数中始终可见。

**E. 底部按钮**
- 左侧："文件预览"文字按钮（读取时刻快照，原 `plan` 功能）。
- 右侧：次要“关闭” + 主要“下载”；关闭不等于取消主窗口正在执行的下载。
- Ctrl+Enter 提交下载；多行输入框中的 Enter 换行，IME 组合态不提交。按钮获得焦点时 Enter/Space 执行该按钮；其他编辑字段不绑定全局 Enter 下载。
- 解析尚未完成、没有勾选有效结果、当前结果已过期或主窗口忙碌时，“下载/文件预览”禁用并显示原因。选中来源存在读取错误时不能带错误来源直接提交。
- 部分成功时明确显示“可下载 N 个来源 / M 集；X 个来源失败，未加入下载”，并提供查看失败与“重试识别失败项”；用户点击下载即提交当前明确勾选的成功项，不无声丢弃失败行。

### 7.4 状态流转

| 状态 | 输入区 | 结果区 | 下载按钮 |
|------|--------|--------|----------|
| 初始 | 空，聚焦 | 隐藏 | 禁用 |
| 输入中 / IME 组合态 | 可编辑，旧结果作废 | 提示等待输入完成 | 禁用 |
| 等待账号验证 / 当前操作结束 | 可编辑，只保留最新待解析内容 | 显示具体等待原因 | 禁用 |
| 解析中 / 停止旧解析 | 可编辑，修改立即作废旧结果 | 加载状态，错误逐行保留 | 禁用 |
| 部分失败 | 失败行给出原因 | 成功项可勾选，失败项明确未提交 | 完成全部读取且空闲、有效勾选非空时可用 |
| 全部成功 | 可编辑；改动再次作废结果 | 展示 / 摘要 | 空闲且有效勾选非空时可用 |
| 全部失败 | 失败行标红 | 隐藏 | 禁用 |

### 7.5 关键行为

1. **对话框非模态，但不追加下载队列**：下载期间可以打开并编辑下一份草稿；显示“当前下载结束后自动识别”，解析、预览和提交等待当前操作结束。
2. 成功创建并启动下载批次后关闭对话框，任务进入列表并滚动到新任务；提交失败保留草稿并给出原因，不先清空输入。
3. “关闭”/Esc 保留本次会话内的输入与选项，停止待执行解析并协作取消该草稿的活动解析；已经提交的下载不受影响。重新打开时仅复用输入及账号版本仍匹配的结果，否则自动重解析。成功提交后新建草稿不重复恢复已提交内容。
4. 文件预览使用当前有效勾选与参数快照，独立只读窗口展示；不创建下载历史，实际下载仍重新检查权限、冲突与提交。预览窗口关闭只取消预览，不取消另一操作。
5. “调整参数后重试…”复用同一对话框，但使用独立重试上下文，固定所选任务/来源身份并显示原参数。若已有新建草稿，先保留草稿再切换模式，不把新链接混入重试；关闭重试后可恢复原草稿。同一时刻只显示一个编辑上下文，重试仍需明确提交。

### 7.6 自动解析、账号验证与下载的调度

- **1.7.4 保留一个活动后台操作**：账号查询、链接解析、登录、文件预览、下载、诊断互斥；网络和 FFmpeg 工作在 worker 中，主线程保持可编辑和可查看。
- 自动账号验证在启动/凭据变更后排入 GUI 控制器；首次自动解析先等待已排入的账号验证结束。验证网络失败后显示待验证，可继续用现有客户端规则解析，不无限阻塞或自动循环重试。
- 下载中既不启动自动账号查询，也不启动草稿解析；操作结束后先完成必要账号验证，再解析当前仍打开草稿的最新版本。手动动作复用同一控制器，不能绕过忙碌限制。
- 自动解析的待执行请求只保留最新草稿版本，不为每次击键排一个任务。每次解析串行读取合法来源，首期不增加网络并发；“重试识别失败项”只重试当前版本的失败来源。
- 用户改变输入或进入 IME 组合态，立即作废旧提交资格，并取消旧解析；等待旧 worker 真正结束后才能启动下一次解析。协作取消可能等待现有网络请求超时，界面显示“正在停止旧识别…”，不强制终止线程。
- 用户明确点击“取消解析”时清除该次待执行请求并保留草稿，显示“已取消识别”；不因 worker 结束或对话框仍打开就重启同次解析。再次编辑输入或手动“重新识别”才重新调度；自动账号验证被取消后同样等待凭据变更或手动刷新，不循环自启。
- 本节的待执行动作是 GUI 的短期调度状态，不是可运行中追加的下载队列，不持久化，也不改变 Session 的单活动批次约束。

### 7.7 解析上下文与生命周期

- 每次读取绑定草稿 ID、输入 generation、账号/凭据 revision 与 job ID；逐行结果绑定稳定来源标识，不能仅按当前输入行号回填旧请求。
- 修改链接、退出/重新登录、凭据版本变化或账号权限状态变化时，使相关结果及选集提交快照失效。相同链接的不同输入位置仍分别保存选择。
- 过期事件、done 回调和取消结果都不得覆盖当前草稿、账号状态或下载状态；不能只过滤中间结果而允许旧 done 改写新一轮状态。
- 普通编辑可自动重解析；读取失败不无限自动重试。保留“重新识别”/“重试识别失败项”恢复入口，但自动解析仍是默认流程。
- 关闭对话框、退出程序及隐藏到托盘时，控件与 worker 生命周期有明确归属。隐藏不销毁草稿/worker；实际关闭后待执行解析取消，活动 worker 由控制器持有直至结束，不删除运行中的 QThread。

## 8. 状态栏

### 8.1 布局

| 区域 | 内容 |
|------|------|
| 左侧（可拉伸） | 当前操作的文字提示，例如"正在读取 2 个链接"、"已取消"、操作失败原因 |
| 中间 | 本批摘要，例如“下载中 1 · 等待 1”；未完成发现时注明“已发现 N 项” |
| 右侧 | 登录状态标签（点击展开账号菜单）、唯一的当前操作取消入口 |

### 8.2 要点

- 使用 Qt 原生状态栏控件，而不是手工拼的底部布局。
- 账号标签和取消按钮放入 permanent widgets，不被临时提示遮挡；长提示省略显示并提供完整 tooltip。
- 空闲时**不再显示使用说明**。原来那句"多 P 默认全部；链接指定 P 时仅下载该 P"迁移到新建下载对话框的选集区域旁，用一行灰色提示或问号 tooltip 承载。
- 取消按钮只在有活动操作时显示，空闲时隐藏而不是灰掉。
- 按实际操作显示“取消本批下载 / 取消解析 / 取消预览 / 取消登录 / 取消账号验证 / 取消诊断”。“取消本批下载”包括本批正在执行及尚未执行的项目，不是单项取消，也不是取消下一份未提交草稿。
- 点击取消后显示“正在取消…”，禁用重复点击，待 worker 结束后才进入已取消/空闲状态。取消与主窗口/新建对话框的“关闭”分开。
- 临时提示（成功、已复制路径等）显示数秒后自动恢复为队列摘要。
- 下载结束摘要保留至下一次操作，不被“已复制”等短提示永久覆盖；后台自动账号检查不擦除上一批下载结果。

### 8.3 登录状态的表达

| 状态 | 文案 | 视觉 |
|------|------|------|
| 未登录 | 未登录 | 灰点 |
| 凭据存在，等待调度 | 凭据待验证 | 黄点，tooltip 说明等待原因 |
| 正在验证 | 正在验证账号… | 黄点或轻量加载标识 |
| 验证成功 | 已登录：昵称 · 普通账号/大会员 | 绿点，账号页展示更完整信息 |
| 服务确认已失效 | 登录已过期 | 红点，提供扫码入口 |
| 文件不可读/格式错误 | 凭据不可读 | 红点，tooltip 说明修复方式 |
| 网络失败/取消，尚未验证 | 凭据待验证 | 黄点，说明网络失败/已取消，可手动重试 |

### 8.4 账号自动解析与验证（1.7.4 必做）

这里“自动解析账号”指：检测现有 `Settings.token_file` 中的 token/Cookie 信息，并调用既有 `auth.status` 自动验证有效性、读取昵称与普通/大会员状态。不是从 token 字符串猜账号，不自动生成二维码，也不改动凭据保存格式。

1. 先显示主窗口，再离线检查本地配置与凭据。有可读取、格式合法的 token 时显示待验证并自动安排一次后台账号查询；没有 token 时显示未登录，不发送账号验证请求，不妨碍匿名链接解析。
2. 查询成功后更新主窗口与账号页各入口所用的同一份状态；会员标记只反映查询结果，不保证对具体视频有下载权限。
3. 本地 token 存在不等于登录成功。服务器确认失效时标记过期；网络失败、超时或取消不得改称过期，也不自动删除 token、清空输入或循环弹出错误框。格式损坏/不可读需明确提示修复或退出登录，不悄悄丢弃凭据伪装成匿名成功。
4. 扫码登录成功后自动查询账号，无需另点按钮；退出登录立即使账号结果、待执行验证与相关解析快照失效，旧查询返回不能恢复为已登录。
5. 同一凭据版本在启动或变更后只自动验证一次。重新打开草稿、账号页时检查凭据是否已改变；外部 CLI 更新/删除 token 后重新验证或切换为未登录。无需高频文件轮询；保留手动“重新验证账号”。
6. 账号验证与链接自动解析按第 7.6 节串行调度；等待验证期间可编辑草稿。验证网络失败不无限阻挡解析/下载，现有客户端仍按真实请求与权限处理，不把 UI 账号结果当作授权依据。
7. 不复制 token 到草稿、GUI 偏好、历史、诊断、通知或日志；账号查询事件绑定凭据 revision/job ID，拒绝过期结果。

## 10. 视觉规范

### 10.1 总体风格

- 干净、扁平、留白充足；少用边框，多用背景色差与间距划分区域。
- 圆角统一：控件 6 px，对话框 / 卡片 8 px。
- 阴影仅用于弹出层（菜单、对话框），主窗口内不使用。

### 10.2 样式基底

- 使用 Qt 的 **Fusion** 样式作为统一基底，让控件间距、状态和不同 Windows 版本的外观保持一致。
- 在此基础上自定义调色板与一份全局样式表，集中管理，不在各控件上分散写样式。
- 基础浅色与深色均进入本版验收，默认跟随系统；系统主题/调色板变化时更新样式和图标，不能只在启动时检测一次。禁用、选中、失焦与高对比状态也须可读。手动三选一主题设置后置。
- Fusion 在现有 Qt 环境可用；不增加第三方 UI 框架。采用它不等于所有自定义颜色自动适配。

### 10.3 颜色

| 角色 | 浅色 | 深色 | 备注 |
|------|------|------|------|
| 窗口背景 | 浅灰白 | 深灰 | 与列表区略有差异 |
| 列表 / 卡片背景 | 白 | 略浅于窗口的深灰 | |
| 主文字 | 近黑 | 近白 | |
| 次要文字 | 中灰 | 中灰 | 摘要、提示、占位 |
| 强调色 | 品牌蓝（沿用现有 `#2859c5` 附近） | 稍提亮的蓝 | 仅用于主按钮、选中、进度 |
| 成功 / 警告 / 错误 | 绿 / 琥珀 / 红 | 同色相，亮度调整 | 必须搭配图标或文字 |

> 具体品牌/语义色在实施阶段统一定义为设计 token；通用色结合系统调色板生成。控件引用同一组值，不在各处硬编码；系统高对比模式优先可读性。

### 10.4 间距与尺寸

| 项 | 数值 |
|----|------|
| 窗口内边距 | 16–20 px |
| 区块之间 | 16 px |
| 同一区块内控件之间 | 6–8 px |
| 控件最小高度 | 32 px（输入框、按钮、下拉统一） |
| 列表行高 | 36–40 px |
| 工具栏高度 | 44 px 左右 |

### 10.5 字体

- 使用 Qt 获取的系统默认 UI 字体及字体回退，不强制指定微软雅黑或 Segoe UI。
- 字号阶梯：正文 9–10 pt，标题 12 pt，应用名 / 空状态主文案 14–16 pt；避免出现三种以上字号。
- 次要信息用颜色区分，而不是缩小到难以阅读。
- 上述尺寸为 Qt 逻辑像素，结合字体度量，不再次手动乘 DPI；小窗口与字体增大时优先折叠低频操作，保证主要控件可见。

### 10.6 图标

- 应用 Logo 与托盘图标继续使用 1.7.2 起的原创图标；操作图标采用少量自绘线性 SVG，作为项目源码保存，不引入外部图标库。
- 单色操作图标由 GUI 图标工厂按主题、禁用状态和 DPI 渲染/缓存；不能假定 SVG 的 `currentColor` 会自动跟随 QIcon 的控件文字颜色。
- 工具栏按钮为"图标 + 文字"，不使用纯图标，保证可发现性。
- 实施时补齐图标资源收集与 SVG 渲染支持，并核对冻结程序；现有构建只显式收集 `bilix-*.png`，源码可加载图标不代表独立发行包也可加载。首期不为图标安装完整 PySide6 Addons。

### 10.7 按钮层级

| 层级 | 外观 | 用法 |
|------|------|------|
| 主按钮 | 强调色填充 | 每个界面至多一个：新建下载、下载 |
| 次要按钮 | 描边或浅底 | 取消、选择…、预览 |
| 文字按钮 | 无边框，悬停出现底色 | 工具栏条目、"更多选项"、链接式操作 |

## 11. 交互与细节

| 项 | 说明 |
|----|------|
| 剪贴板识别 | 用户打开空草稿或在主窗口按 Ctrl+V 时读取一次；包含支持的链接/BV 号则预填并自动解析；不后台监听剪贴板，不覆盖非空草稿 |
| 拖拽 | 支持拖入链接文本、`.txt` 链接列表 |
| 快捷键 | Ctrl+N 新建；Ctrl+O 导入；Ctrl+, 设置；Ctrl+Enter 下载；不提供 Delete 任意移除 |
| 键盘可达 | Tab 顺序合理，输入框 Enter 换行，Esc 关闭当前对话框；列表菜单可通过“更多操作”、菜单键/Shift+F10 到达 |
| IME 兼容 | 保留占位文字与 Ctrl+Enter 保护，并扩展到防抖解析；组合态既不提交，也不发起解析 |
| 最小化到托盘 | 本版必做，能力检测、恢复与退出按第 11.1 节 |
| 下载结束通知 | 本版必做，以批次为单位，语义与回退按第 11.2 节 |
| 窗口记忆 | 保存窗口尺寸、位置、列宽及安全选项；详情见第 11.3 节 |
| 高 DPI | 图标与 Qt 逻辑尺寸配合，在 125% / 150% 下检查，不能仅凭 SVG 就宣称适配通过 |
| 无障碍 | 为控件设置可访问名称；状态不只靠颜色表达 |

### 11.1 最小化到托盘（1.7.4 必做）

- 使用 QSystemTrayIcon 与已有应用图标；设置“最小化到托盘”默认开启。先检查 `isSystemTrayAvailable()` 并创建有效托盘入口，再响应最小化隐藏主窗口及该窗口当前可见的草稿/预览等附属窗口，恢复时还原其可见状态；不停止下载或销毁草稿。
- 托盘菜单提供“显示主窗口 / 新建下载 / 打开默认下载目录 / 退出”。支持可用的点击/双击恢复方式，菜单中的“显示主窗口”始终作为恢复入口，不依赖某一 Linux 桌面一定支持双击。
- 恢复时显示并激活原窗口，保留原来的正常/最大化状态、列表与草稿；新建下载先恢复窗口，再打开/聚焦草稿。重复激活不重复创建窗口。
- **最小化与关闭不同**：最小化可进托盘；标题栏关闭、Alt+F4、文件菜单退出和托盘退出都进入同一显式退出流程，不把关闭偷偷改成隐藏。
- 实际下载运行时退出需确认停止本批；仅有自动解析/账号查询等读取操作时取消读取并等待结束。确认退出后停止所有待执行自动动作，协作取消活动 worker，等待清理和线程结束，再释放托盘与退出；拒绝退出则保持运行。不以强制终止线程实现退出。
- 当前桌面无托盘、用户关闭此偏好，或托盘能力消失时，使用普通任务栏最小化/恢复。若主窗口已隐藏，应自动恢复可见入口；不得留下用户无法恢复的后台窗口。无托盘时不要求安装桌面扩展或新依赖。
- 窗口隐藏时后台失败写入状态与详情，不弹出不可见的模态框卡住线程；退出确认先恢复主窗口。应用生命周期应显式管理，既不能隐藏后意外退出，也不能关闭所有窗口后无出口地驻留。

### 11.2 下载结束通知（1.7.4 必做）

- 设置“下载结束通知”默认开启。使用系统托盘通知；有可用托盘且 `supportsMessages()` 为真时尝试发送，窗口是否最小化不影响批次结果记录。
- 每个真正提交的下载/重试批次完成一次汇总，只发一次通知，不为每个 P、流进度、自动解析、账号查询、登录或文件预览发完成通知。
- 全部完成/跳过显示“本批下载完成”；包含媒体或来源读取失败显示“本批下载已结束，有失败项目”，正文区分完成、跳过、失败和读取失败数量。用户主动取消只保留取消摘要，不发误导的“完成”通知。
- 通知不显示 token、账号昵称、完整路径、视频标题或签名 URL，默认只包含 BiliX 与本批数量。点击通知恢复主窗口；能关联批次时展示对应摘要，通用托盘接口无法区分旧通知时展示最近通知批次并保留批次详情入口，不声称精准跳转旧通知。不能因通知点击再次开始下载。
- 系统可能禁用或抑制通知，不能保证送达。无通知能力、发送失败或偏好关闭时，列表、底部结束摘要与批次详情仍完整保留，不用阻塞弹窗替代，不把通知失败当成下载失败。
- 去重按 batch ID，旧完成事件、重复回调、恢复窗口或重新打开详情不再通知。退出清理时不继续弹出通知。

### 11.3 GUI 偏好与诊断复制

- GUI 偏好独立于 `config.toml`，可用 QSettings 保存版本化的窗口位置/尺寸、列宽、上次画质/编码/音轨、严格匹配及托盘/通知开关；不改变 CLI 默认配置。
- 不保存 token、账号资料、解析结果、媒体地址或草稿。覆盖同名文件始终在新会话默认关闭；其他非默认媒体选项恢复后仍显示摘要。
- 偏好缺失、损坏或保存失败可回退到安全默认；恢复位置须裁剪到当前屏幕可用区域，断开原显示器后也能找到窗口。
- 设置中的托盘/通知开关通过“确定/应用”保存，取消只丢弃未应用修改。自动保存窗口几何与列宽不等于业务配置修改即保存。
- “复制诊断信息…”先展示白名单摘要，含程序/Python/Qt/FFmpeg 版本、安全状态和选定统计；默认省略完整路径、用户名、账号、标题、URL、原始配置和凭据。不能把现有 doctor 文本中的全部路径直接复制到公开反馈；本版不实现通用诊断导出文件协议。

## 12. 对现有代码的影响（定性）

### 12.1 保持不变

- 下载引擎与业务层：`service`、`tasks`、`planner`、`media`、`bilibili/*`、`auth`、`config` 等。
- 任务 ID、尝试快照、Session 单活动批次约束及业务事件语义；HistoryModel 保留现有主结构，不另建下载队列。
- 既有后台线程与协作取消机制。GUI 控制器、worker 适配层、进度角色和状态映射可以调整，以承接自动调度与生命周期保护；不能把“下载内核不改”误解为 GUI 状态代码完全不改。

### 12.2 需要调整

| 模块 | 调整内容 |
|------|----------|
| `gui/panels.py`（`CompactUi`） | 主窗口改为“菜单栏 + 工具栏 + 筛选标签 + 列表 + 状态栏”，表单迁出，新增空状态 |
| 新建下载对话框 / 草稿上下文 | 承接输入、逐行校验、500ms 防抖、自动解析、选集、保存目录、参数、预览与固定身份的重试模式 |
| `gui/app.py`（`MainWindow`）及 GUI 控制器 | 主窗口负责任务提交、列表和应用生命周期；控制器统一活动操作、待执行账号验证/最新草稿、generation/revision/job ID 及取消收尾 |
| HistoryModel / GUI worker 适配 | 增加数值进度角色、统一计数、来源重读关联与终态更新；用 delegate 绘制，不创建每行控件 |
| 账号 / 设置 | 自动发现本地 token 并验证；各账号入口共享状态；三页紧凑布局与确定/取消/应用 |
| 状态提示 `_message` | 使用 QStatusBar，保留账号/取消常驻控件、临时提示和批次结束摘要 |
| 动作与忙碌状态 | 菜单、工具栏、右键共用 QAction 与启用条件；忙碌时允许准备草稿，阻止解析/提交等互斥操作 |
| 样式 / 图标 / 打包资源 | Fusion、浅深色调色板、统一样式和图标工厂；新增 SVG 进入源码与冻结包 |
| 托盘 / 通知 / 退出 | 最小化与恢复、能力回退、显式退出和线程收尾；按真实批次终态通知并去重 |
| GUI 偏好 / 诊断 | 独立 QSettings、屏幕范围恢复、安全默认值；白名单诊断摘要预览与复制 |

### 12.3 主要风险

1. **过期回调与退出收尾**：输入修改、草稿关闭、凭据变化后，旧结果和旧 done 都要被拒绝；控制器仍负责等旧线程真正结束，避免释放运行中的 QThread。
2. **自动操作抢占下载**：账号验证与解析必须通过同一串行控制器；下载中只准备草稿。显式取消解析后不能立即自动重启同一次识别，必须等待再次编辑或手动重新识别。
3. **账号状态误判**：凭据存在、服务器确认有效、网络失败、文件损坏是不同状态。外部 CLI 修改 token 或退出登录后，旧验证不能回写成功。
4. **选择与重试身份**：部分成功、重复链接、多 P 范围和重读来源不能错配；新草稿参数不能混入固定身份的重试。
5. **列表性能与完成语义**：数值进度、筛选计数与按钮启用须同源；传输 100% 后还可能校验/合并/保存，不得提前显示完成或发通知。
6. **托盘可恢复性与通知限制**：桌面支持程度、通知抑制、隐藏时错误、关闭/退出路径都要有回退；不存在托盘时绝不能留下不可恢复的隐藏窗口。
7. **主题与冻结包差异**：Fusion 不会自动修正所有手写颜色；SVG 在源码环境可用也不代表冻结包包含资源和渲染支持。
8. **旧用户习惯与可发现性**：入口迁移后保留空状态引导、文字按钮和键盘动作，不让功能只存在于悬停/右键中。

## 14. 实施建议

整体难度为**中等偏高**：菜单/布局/设置相对容易，主要工作量在自动调度、草稿/账号生命周期、列表数值展示与托盘退出收尾。下载内核不动能控制范围，但这一轮比纯外观调整更大；不预设“只改布局即可完成”的工期。

建议分阶段实施，阶段是开发顺序，不是删除本版必做项的理由：

| 阶段 | 内容 | 产出 |
|------|------|------|
| **P0 基础** | 统一动作/忙碌条件和操作上下文；保留 Session 约束；建立 Fusion、主题及图标资源方案 | 为自动调度与外观提供共同基础 |
| **P1 外壳** | 菜单、工具栏、QStatusBar、空状态；账号/设置入口迁移，逐步迁出旧表单 | 主窗口以列表为中心，原功能入口保留 |
| **P2 自动流程** | 草稿与重试模式、逐行校验/自动解析、选集、预览、token 自动验证、过期回调与取消保护 | 粘贴后自动识别；有凭据自动显示经验证的账号；下载中草稿等待 |
| **P3 列表与设置** | 筛选/计数、数值进度、delegate、选中行菜单、设置三页及确定/取消/应用 | 展示准确、操作可发现，参数保存语义一致 |
| **P4 托盘与交付检查** | 最小化/恢复/退出、批次通知与回退、QSettings、快捷键/IME/拖拽/剪贴板、安全诊断和冻结资源 | 全部 1.7.4 必做项形成完整流程，完成有针对性的验收 |

### 验收方式与边界

沿用用户要求的简洁测试：运行现有相关 GUI 检查，为新增调度与状态边界补少量定向检查；网络成功/失败和旧回调尽量用可控模拟验证，不扩大到下载内核、平台权限与安装环境的全面矩阵。文档中的验收项尚未执行。

| 场景 | 必要结果 |
|------|----------|
| 空状态与主流程 | 入口清晰；粘贴单视频到开始下载不超过 3 次点击；原登录、预览、选集、重试、清除、导入、诊断均可到达 |
| 输入与自动解析 | 单/多链接、重复来源、`?p=`、范围应用、部分失败结果明确；快速编辑、粘贴、IME、关闭再打开不提交旧结果；显式取消不自启同次请求 |
| 账号自动验证 | 无 token、有效/过期 token、网络失败、损坏文件、登录后验证、外部 token 改变与退出后的旧回调均符合第 8.4 节，无循环请求 |
| 忙碌与重试 | 下载中草稿可编辑，读取/提交等待；只有一个活动操作；取消作用于当前操作；重试保留选中身份与参数来源，清除不删文件 |
| 进度与计数 | 未知大小不伪造百分比；传输结束不提前完成；媒体/来源终态计数、筛选与重试启用一致；进度刷新不重建全树 |
| 设置与偏好 | 确定/应用保存，取消未应用编辑；保存失败不关闭；恢复列宽/位置不跑出屏幕；覆盖不跨会话恢复；诊断无敏感信息 |
| 主题与尺寸 | 基础浅/深色及运行时切换可读；125%/150% 无主要控件截断；约 700×540 的主窗口及可用屏幕内的对话框可操作，必要时折叠/滚动 |
| 托盘生命周期 | 下载中最小化后仍运行，菜单恢复原窗口；无托盘/能力消失时保留可见入口；关闭确实退出，取消退出继续运行，无悬挂线程或隐藏模态阻塞 |
| 通知 | 真实批次结束只通知一次；失败摘要准确，解析/账号/预览/主动取消不发完成通知；关闭/不支持/被系统抑制不影响下载与结束摘要 |
| 独立发行包 | 新 SVG 与品牌图标可加载；冻结 GUI 能启动、打开对话框、恢复托盘并退出；发布时核对资源，不把源码启动代替包验证 |

实际人工检查以一轮 Windows 原生主流程为主，串起“自动账号 → 粘贴/选集 → 预览/下载 → 托盘恢复 → 结束摘要/通知 → 重试/退出”；用现有 Linux GUI 环境补一次托盘能力/无能力回退检查即可，不为此强制新建完整多桌面测试矩阵。自动通知送达只记录该环境的实测，不能据此保证所有桌面均可收到。

## 15. 已统一的 1.7.4 决策

| 问题 | 本版结论 |
|------|----------|
| 链接是否自动解析？ | 必做，输入稳定约 500ms 后启动；IME、取消、旧回调及部分失败有明确保护 |
| 账号是否自动解析？ | 必做，有合法本地 token 自动调用现有账号查询；没有 token 不发查询，网络错误不判定过期 |
| 解析与下载是否并行？ | 不并行，保持一个活动后台操作；非模态对话框只准备草稿，等待当前操作后自动识别 |
| 是否支持运行中追加/单项删除？ | 本版不做；取消下载以批次为单位，清除沿用按状态清记录 |
| 已取消是否独立筛选？ | 独立标签；等待归进行中，完成/跳过一组但语义分别展示 |
| 重试用什么参数？ | 默认原快照；调整参数后重试进入固定身份的独立上下文并明确提交，不借用另一份草稿 |
| 设置怎么保存？ | 确定 / 取消 / 应用；已应用配置及已完成登录操作不回滚 |
| 主题支持到什么程度？ | Fusion 与基础浅/深色、运行时系统变化、禁用/选中状态均必做；手动主题选择后置 |
| 操作图标选什么？ | 少量自绘 SVG + 统一图标工厂，现有原创 Logo 保留；补齐冻结资源，不增加完整 Addons |
| 拖拽与剪贴板是否加入？ | 本版加入；剪贴板仅在用户打开空草稿或主窗口 Ctrl+V 时读一次，不后台监听 |
| 最小化到托盘是否加入？ | 必做，默认开启、有能力才隐藏；恢复保留窗口状态；标题栏关闭与菜单退出仍是显式退出 |
| 下载完成通知是否加入？ | 必做，每个真实批次结束一次汇总；失败文案准确、主动取消无完成通知，能力不足回退至列表/状态栏 |
| 保存哪些偏好？ | 仅明确 GUI 偏好与安全媒体选项；不保存凭据、草稿、解析结果，覆盖跨会话关闭 |
| 本版怎么验收？ | 定向 GUI 状态检查 + 原生主流程 + 轻量发行包检查，不扩展为下载内核全面回归 |
