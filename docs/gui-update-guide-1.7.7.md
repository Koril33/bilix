## 1. 调研结论与版本边界

**可行，不需要更换 GUI 技术栈或添加第三方界面库。** 偏好、固定快捷键和三种主题选择属于低到中等难度；可靠速度/剩余时间属于中等难度，主要工作在进度采样、重试和双流聚合，而非增加文字控件。

| 工作 | 难度 | 本版实际需要的改动 |
| --- | --- | --- |
| GUI 偏好完善 | 低到中等 | 集中读写、明确保存时机、默认值、恢复默认和写失败反馈；分开 GUI 偏好与业务配置 |
| 额外固定快捷键 | 低 | 复用既有动作，明确焦点作用域、忙碌条件和输入法保护 |
| 跟随系统/浅色/深色 | 低到中等 | 在现有 Fusion 基础上增加用户选择、持久化与运行时更新；处理图标、选中状态和高对比提示 |
| 单流速度和传输 ETA | 中等 | 增加流尝试、生产端采样时间和明确的连接/重试/结束状态 |
| 音视频聚合反馈 | 中等 | 有界采样窗口、停滞衰减、未知总量处理、双流估时与线程安全快照 |
| CLI 复用估算器 | 中等，D05 已确认 | 更换 Rich 的速率/ETA 数据来源，保持既有命令及输出模式 |

本版保留 Session 的单活动批次、视频任务串行和单视频双流并行。下载选择、重试次数、备用 URL、取消作用域、字节完整性检查、FFmpeg 校验/合并和原子提交规则继续沿用。**允许改造共享传输反馈接口；“GUI 版本”不代表只改 Qt 控件。**

运行中追加、单项取消/移除、暂停续传、媒体任务并发/限速、跨重启任务历史、JSONL、config 子命令、stdin、通用诊断导出不进入本次范围。软件更新包的下载进度属于 1.7.6 更新器，不混入本版媒体下载速度。

## 3. GUI 偏好方案

### 3.1 存储和建议默认值（D01）

继续使用配置目录内的 `gui.ini`，与 `config.toml`、`token.txt` 分开。Windows installer 与 portable 均沿用现有用户配置位置，不把绿色版改为 EXE 旁保存配置。新增字段采用可选键，兼容读取已有 `v1` 分组，不为新增几个选项强制迁移整份文件。

| 偏好 | 建议默认 | 保存/生效方式 |
| --- | --- | --- |
| 主题 `themeMode` | `system`；另有 `light`、`dark` | 设置点击应用/确定保存，立即重绘 |
| 记住下载选项 `rememberMediaOptions` | 开启，接续已有体验 | 保存成功提交下载时的画质/编码/音轨/strict；恢复用于下一次空白草稿 |
| 显示速度与传输剩余时间 `showTransferFeedback` | 开启 | 设置应用后立即改变显示，不停止采样和下载 |
| 更多选项展开 `advancedExpanded` | 折叠 | 记忆用户展开状态；改变展开不改变下载参数 |
| 窗口几何和列宽 | 沿用已有值 | 正常退出保存；保存的是正常窗口几何，不能记成隐藏/最小化启动 |
| 托盘、完成通知、自动检查更新 | 沿用用户设置，缺失时仍开启 | 接续 1.7.6 语义及 30 分钟频率，不重新询问已确定的政策 |
| 任务筛选 | 每次新会话/新批次显示全部 | 本版建议不记忆，避免新任务被旧筛选隐藏 |
| 本次下载目录 | 建议不记忆 | 仍使用业务默认与当前草稿；需要长期修改目录时使用现有默认目录设置 |

关闭“记住下载选项”后，下一次空白草稿使用最高可用画质/自动编码/AAC/strict 关闭；保留当前草稿与已提交任务的快照。已有草稿的打开、编辑、取消、原参数重试继续保持既有语义。

**覆盖同名文件不保存、不自动恢复，每次新会话仍关闭。** strict 或其他非默认媒体选项恢复后继续显示摘要，折叠更多选项也不能隐藏它们。偏好不保存凭据、账号资料、链接、媒体 URL、选集或任务历史。

### 3.2 设置交互与恢复默认（D02）

保留设置窗口现有“账号/常规/诊断”结构。在常规页增加紧凑的“界面”区域，不增加主窗口常驻设置条。主题、记忆选项和反馈显示一起通过“应用/确定”保存；点击取消恢复到最后已应用状态。建议不做未保存的即时主题预览，简化取消与回退。

GUI 外观设置在读取/下载/校验/合并期间均可应用。业务默认目录和 FFmpeg 路径仍遵守既有空闲编辑约束；不能因放开主题按钮而放开互斥操作，也不能将保存 GUI 偏好误报为修改既有下载参数。

增加 **“恢复界面默认…”**：先显示将恢复的项目，确认后重置主题、媒体记忆/默认媒体选项、反馈显示、展开状态、窗口布局与列宽；新媒体默认只影响后续空白草稿。保留托盘、通知、自动更新开关，以及 `config.toml`、凭据和下载文件。按钮名称和提示不能写成“恢复软件所有设置”。

### 3.3 读写、异常与兼容

- 增加轻量 GUI 偏好适配模块，统一默认值、键名、允许值和持久化反馈；QSettings 对象只在 GUI 线程使用。传输线程不读取或保存 GUI 偏好。
- 数字列宽有上下界；未知主题枚举回到跟随系统；布尔/画质/编码/音轨按类型及现有枚举校验，不能用 Python `bool("false")`。未知键保留，恢复默认只移除明确列出的键，禁止 `clear()` 整份配置。
- 保持 QSettings 原子同步要求；保存后检查 `sync()`/`status()`。不能为了无权限目录而关闭原子写入。GUI 与业务文件没有跨文件事务，某一项失败要准确提示哪部分已保存，不写笼统“设置已保存”。只修改 GUI 项时不调用业务配置写入。[QSettings 原子同步与错误状态](https://doc.qt.io/qt-6.10/qsettings.html#isAtomicSyncRequired)
- 缺失字段采用默认值；格式损坏时窗口仍能打开，提示一次并在用户明确恢复时备份旧 `gui.ini`、重建 GUI 偏好。业务文件损坏时仍允许读取界面偏好，不静默修复或覆盖业务文件。
- 配置目录按 `BILIX_CONFIG_DIR` 或既有 platformdirs 规则定位；不能依赖业务 TOML 成功解析，也不能因解析失败写入另一份注册表设置。定位/写入失败时用本次会话的安全默认并明确“未保存”。
- `saveGeometry()/restoreGeometry()` 之外继续复核当前屏幕可用区域与最小尺寸；断开显示器、DPI 变化、Wayland 不允许程序决定位置时保持窗口可访问，不承诺绝对坐标完全恢复。[Qt 窗口几何恢复](https://doc.qt.io/qt-6.11/restoring-geometry.html)
- 多实例只做键级保存，后写同一键生效；本版不引入配置实时同步服务。1.7.6 回退客户端忽略新增键，原有媒体和更新开关可继续读取；不改变安装身份。

## 4. 快捷键方案（D03）

建议本版使用固定按键，新增“帮助 → 快捷键…”入口及 F1，帮助文本来自同一动作表。暂不添加按键录制、冲突编辑器或快捷键配置文件。

| 按键 | 动作 | 作用域与启用条件 |
| --- | --- | --- |
| Ctrl+N / Ctrl+O / Ctrl+, | 新建 / 导入链接文件 / 设置 | 保留现有入口和忙碌规则；设置可打开查看 |
| Ctrl+V | 向空草稿粘贴支持的链接并解析 | 主窗口行为保留；编辑框内仍是正常粘贴，不拦截或覆盖已有草稿 |
| Ctrl+Enter、Ctrl+Return | 提交下载 | 仅下载对话框；主键盘和数字键盘分别覆盖；同一次按键只提交一次 |
| Shift+F10、菜单键 | 当前列表对象的菜单 | 下载列表有焦点且有有效选中对象 |
| **Ctrl+D** | 查看详情 | 列表焦点，沿用现有详情对象选择规则 |
| **Ctrl+R** | 重试选中项，沿用原参数 | 列表焦点，空闲且所选对象允许重试；包含不允许重试对象时不部分偷偷执行 |
| **Ctrl+Shift+O** | 打开选中项所在目录 | 列表焦点，复用现有目录可用条件；不偷偷改为另一个默认目录 |
| **Ctrl+Shift+C** | 复制选中项路径 | 列表焦点，复用现有路径可用条件 |
| **F1** | 快捷键帮助 | 当前 BiliX 主窗口或本程序对话框；不是系统全局快捷键 |
| **Ctrl+Q** | 明确退出应用 | 主窗口；调用现有退出/取消等待逻辑，下载中继续询问，不等同关闭到托盘 |
| Esc / Tab / Shift+Tab | 关闭当前对话框 / 焦点移动 | 保持 Qt 常规行为；Esc 不新增为取消整批下载 |

菜单、工具栏、右键与按键复用相同动作和启用条件；不能另写一套快捷键业务逻辑。列表动作优先用 `WidgetWithChildrenShortcut`，窗口动作使用对应窗口作用域，不用 `ApplicationShortcut` 抢占其他对话框的输入。

提交、重试、退出等动作关闭按住自动重复。处理 `ShortcutOverride` 与输入法组合态，禁止组合输入时下载/重试；不改变文本框普通 Enter 换行。不能同时重复绑定 QAction 与 QShortcut，歧义触发不选一个动作强行执行。Qt 官方文档明确区分快捷键上下文、自动重复和歧义信号；本版需据此核对绑定。[QShortcut](https://doc.qt.io/qt-6.10/qshortcut.html)

## 5. 主题增强方案

### 5.1 三种选择

“跟随系统 / 浅色 / 深色”三选一，默认跟随系统。用户选择在应用后立即生效，重启保持。继续使用 Fusion、现有蓝色强调色及 SVG 图标，不增加 Fluent 库、皮肤市场或品牌颜色编辑器。

- 手动浅/深色使用应用自己的明确调色板，不仅调用系统主题提示；系统提示不保证每个平台都接受覆盖。
- 跟随系统才响应系统浅/深变化；系统报告 Unknown 时回到可读的浅色默认，不按本应用已修改的调色板反推系统主题。
- 在显示主窗口前读偏好并应用主题，避免启动先浅后深的闪烁。保持 `colorSchemeChanged` 与 palette 事件的协调、重入保护和合并刷新，不能在收到本应用生成的 palette 事件时无限重新 `setPalette()`。
- 主窗口、下载/设置/详情/预览/关于/快捷键/消息框均更新；操作图标、禁用图标、选中行、失焦状态、提示文本、水平进度条同步刷新。系统标题栏和文件选择器仍受平台支持限制。

Qt 提醒：主题变化信号发出时旧调色板可能仍在使用，应用显式设置过的颜色也不会自动被系统覆盖。本版据此把主题选择、有效调色板及重绘集中管理，不能只是给下拉框绑定原 `apply_theme()`。[Qt 6.11 QStyleHints](https://doc.qt.io/qt-6.11/qstylehints.html#colorScheme-prop)

### 5.2 高对比与可读性

锁定依赖为 `PySide6-Essentials==6.11.2`；Qt 6.10 起提供高对比偏好查询。建议系统明确报告高对比时优先使用受控的高对比配色与明显焦点边框，暂时覆盖品牌配色，保留已保存主题选择，解除后恢复。不同 Linux 桌面的主题/高对比上报能力需要原生核实；未上报时保持手动主题可选及文字/符号提示，不宣称所有平台都有自动高对比适配。[QAccessibilityHints](https://doc.qt.io/qt-6.11/qaccessibilityhints.html)

将 WCAG 的普通文字 4.5:1、关键非文字状态 3:1 用作自定义界面的工程检查参考；这是可读性目标，不宣称完成整个 WCAG 合规审计。速度、失败、完成等不能只靠颜色区分。[文字对比参考](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比参考](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 6. 速度与剩余时间的用户体验（D04）

### 6.1 显示位置

建议保留“视频/选集、状态、进度、操作”四列，不增加速度和 ETA 两个常驻列。**进度单元格保留音视频水平条，下面增加一行总速度和当前视频的传输估时**：

```text
视频 67%   [──────────────      ]
音频 100%  [────────────────────]
5.2 MiB/s · 传输约 1 分 20 秒
```

初始建议进度列约 220 个逻辑像素、行高约 60，最终值随字体/DPI 检查调整。父行仍展示已结束/已发现数量，不冒充整批进度。为保持 uniformRowHeights，使用统一紧凑行高；关闭反馈显示可回到原有较小行高。列宽不足时优先保证速度，估时适当简写，并在 tooltip/详情提供完整文本和各流数据；工具提示不应是唯一入口。可选中查看详情获取全量文本，盲目扩大窗口最小尺寸不属于解决方案。

状态栏保留当前批次计数；新增反馈不要挤占左下角更新器的下载进度、更新按钮或右侧账号/取消控件。每个任务的速率不含后台软件更新包、其他进程或网卡总流量。

### 6.2 估时语义与文案

**建议仅估算当前视频音视频流的剩余传输时间，不显示整批或完整任务倒计时。** 校验、合并、写入/提交的耗时目前没有可靠模型，待处理视频也未全部取得大小和速率。

| 情况 | 建议展示 |
| --- | --- |
| 正在建立连接或等待响应 | 正在连接；速度/ETA 暂不显示 |
| 样本不足 | 测速中…；传输时间暂无法估算 |
| 正常双流传输 | 合计速度；“传输约 X 分 Y 秒” |
| 任一路总量未知 | 仍显示速度和已下载字节；“传输时间未知” |
| 一路完成 | 完成流保留 100%；速度/ETA 仅取剩余活动流 |
| 网络停滞超过阈值 | 0 B/s · 等待数据；隐藏旧 ETA，不展示无限值 |
| 内部 HTTP 重试/换备用 URL | 重试连接中；受影响流进度复位，旧速率/ETA 清空 |
| 流传输结束但尚未进入后续阶段 | 传输结束，等待校验；不提前写“任务完成” |
| 校验/合并/提交 | 显示对应阶段，停止显示网络速度和传输倒计时 |
| 失败/取消/完成/跳过 | 显示现有结果；清除实时速率/ETA，历史详情可显示确认过的传输统计 |

采用 KiB/s、MiB/s、GiB/s 自动单位，1 KiB = 1024 B，与已有 MiB 进度一致；小值显示 B/s。时间带“约”，正剩余字节不显示“0 秒”；可按 5 秒向上取整以减少跳动，超过一分钟按分秒显示。估时变化是重新计算，不保证倒计时单调减少。

GNOME 的官方进度建议要求估时体现不确定性，并允许无法估算的阶段使用活动提示。本方案据此限定估时范围；它仍保留用户已有的双流反馈，不直接照搬单一复合进度条。[GNOME Progress Bars](https://developer.gnome.org/hig/patterns/feedback/progress-bars.html)

## 7. 共享进度反馈设计

### 7.1 原始采样契约

新增纯 Python 内部数据结构，命名可在实现时调整，但以下字段和语义应冻结并测试。它不是公开 JSONL 协议。

| 字段 | 语义 |
| --- | --- |
| `stream` | 稳定的 video/audio 名称，不含 CDN 地址或临时路径 |
| `stream_attempt` | 从 1 开始的该流 HTTP 尝试编号；与用户重试的 task attempt 分开 |
| `stream_sequence` | 该流尝试内递增采样序号，处理锁外发出导致的乱序/重复 |
| `phase` | connecting / receiving / retrying / finished / failed；finished 在流字节检查通过后发出 |
| `completed_bytes` | 本次流尝试成功写入临时文件的字节数，不包含之前失败尝试的材料 |
| `total_bytes` | 本次响应的有效 Content-Length，缺失时沿用可信的 Stream.size；未知为 None |
| `sampled_at` | 生产端 `time.monotonic()` 时刻，用于差值；不是 GUI 收到信号的时间 |

任务层增加 `batch_id/task_id/task_attempt_id` 关联，并保留既有任务事件版本保护。开始任务时注册必需 video/audio 两路；一路未回调不能被当作无须下载，从而给出错误 ETA。

**在发起每次连接前就发 connecting/复位事件**，不能等新的响应到来才通知重试。响应开始后更新权威总量；取到最后一个 chunk 不等于字节检查通过。流失败和任务终态要分别处理，两路收尾仍按现有事务完成。

可给 `transfer()`、`execute()` 增加可选的结构化反馈关键字参数，保留现有三参数 `progress` 回调的兼容入口；正式任务 runner 优先消费结构化反馈，避免同一 chunk 两次进入 GUI 采样。不能通过捕获任意 TypeError 猜测回调签名，以免吞掉实际错误；更新受影响的内部调用与测试替身。

单调时钟不受系统时间校准影响，适合字节/时间差计算；绝对值不存入偏好或跨重启记录。[Python time.monotonic](https://docs.python.org/3.11/library/time.html#time.monotonic)

### 7.2 速度估算与停滞

新增共享的纯 Python 估算器，不依赖 Qt/Rich，不在 GUI delegate 里累计字节。算法参数是实现初值，不开放为用户配置：

1. 采用最近约 **5 秒**的滑动窗口；至少约 **1 秒**有效观测后展示速率。记录起始计数，速度为窗口内字节增量除以对应时间差，不使用“本次总字节/应用启动时长”。
2. 网络回调每次更新最新计数/状态；估算器采样与 GUI 重绘约 **250ms** 一次。维护有界窗口，不能为每个 chunk 无限添加样本。突发只收到一个 chunk、时间差为零或乱序时不产生异常数值。
3. 空闲 tick 也参与窗口衰减；约 **3 秒**没有新增字节时显示等待数据并清除 ETA。没有回调不等于速度仍是最后一次速率。小流很快结束可以一直没有测速值，不伪造数字。
4. HTTP 新尝试、用户重试、计数回退、总量发生不相容变化时重建受影响窗口。复位属于重要事件不能被限频吞掉；另一条正常流不清零。
5. 同一流的过期尝试/序号丢弃；拒绝负字节、负/非有限时间差、无效总量。已写超过宣称总量时停止估时，交由现有字节检查失败，不能修改总量掩盖错误。
6. finished 流的实时速率为零，不继续用它的历史速度提高总速度；重新取得足够样本后才恢复估时。

### 7.3 双流聚合与 ETA

设每条尚未结束的流剩余字节 `R_i = total_i - completed_i`，有效速度为 `v_i`。

```text
当前视频合计速度 = Σ 活动流 v_i
各流传输估时       = R_i / v_i
当前视频传输估时   = max(各条未完成流的传输估时)
```

合计速度为活动流速率之和；尚未测速/重试的流不提供有效速率，仍可展示其他流的已知速度，并注明等待另一流。两路并行完成时间采用 **max**，不能把两路时长相加。也不直接用“总剩余字节/总速度”，以免一路慢、一路快时低估；后续带宽重新分配仍可能让结果变化，因此始终标注估算。

只有全部未完成的必需流均已开始、总量已知、速率有效且大于零时，才显示当前视频 ETA。任一路 unknown/connecting/retrying/stalled 则聚合 ETA 为 None；完成流不因速率零阻止剩余流估时。所有流确认 finished 后退出传输展示，不能因累计 100% 直接将媒体任务标成完成。

task attempt 不同、失败重试或新视频开始都重新计算；不同历史任务的数据不能汇成当前视频的估时。批次完成/跳过/失败/取消/发现计数沿用既有共享统计和“发现未完成”语义，不创建第二套计数。

### 7.4 线程、事件和 GUI 刷新

两路传输可同时回调。共享反馈状态在短锁内更新计数并冻结快照，锁外调用事件接收者；锁内不做网络 I/O、不操作 Qt、不执行用户回调或配置写入。采样序号与任务事件序号各自明确，不能假定锁外发出的旧快照总是先到达。

建议沿用 Qt 信号传递不可变进度快照；GUI 主线程用一个 250ms QTimer 调用共享估算逻辑，以生产时间采样计算，并补充停滞 tick。这样不为本版再增加常驻采样线程。限频前保留最新状态；开始/复位/流结束/任务终态必须立即交付，终态后晚进度不能复活任务。Qt 跨线程信号使用 queued/auto 连接，不采用 direct 连接操作窗口。[Qt 线程与 QObject](https://doc.qt.io/qt-6.11/threads-qobject.html#signals-and-slots-across-threads)

网络计数更新与前端发事件分开：高频 chunk 更新有界的最新状态，限频快照带各流的生产时刻/序号，不能把每个 chunk 都塞进 Qt 队列。估算器保留实际采样点和有限 tick，不能把信号接收时刻当作下载完成时刻。D05 同期适配时，Rich 的刷新也调用相同纯逻辑的 tick/snapshot，网络回调与渲染线程按线程安全快照交互；即使没有新 chunk，也能清除陈旧速率/ETA。

列表模型增加数值反馈角色，delegate 只绘制。刷新当前活动行及必要摘要，不重建整表、不安装每行 QProgressBar/QTimer。隐藏到托盘后保留必要采样和终态处理，降低无用重绘；关闭/完成后停止相关 timer，清除实时窗口。下次开始正常重新启用。

### 7.5 CLI 兼容选择（D05）

**本版同期让既有 Rich 速度/剩余时间列复用同一估算器**，不新增 CLI 命令、参数或公开事件协议。Rich 支持 `task.fields` 和自定义列，可保留进度条/字节列，用共享数值替代两个默认估算列。[Rich Progress Display](https://rich.readthedocs.io/en/stable/progress.html#columns)

备选 GUI 专用方案本版未采用。未来 JSONL 可复用本版数值语义，仍须另做公开 schema/错误码设计。

无论采用哪个选择，quiet、重定向、dry-run 的既有输出行为、退出码、取消和 CLI 无 Qt 依赖都必须保留。
