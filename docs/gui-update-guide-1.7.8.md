## 1. 结论、版本范围与分阶段建议

**整体可行，无须更换 Qt 技术栈。** 展示与交互优化主要在 GUI；能力提示需要统一媒体选择逻辑；追加任务、单项取消涉及共享调度与取消作用域；真正暂停续传涉及下载事务和网络协议，不能仅增加按钮或复用取消。

复杂度为相对评估，不是工期承诺。以下阶段是实施依赖顺序；全部主线和已确认扩展均进入 1.7.8。

| ID / 原问题 | 可行性与复杂度 | 推荐安排与边界 |
| --- | --- | --- |
| F01 画质/编码与实际能力联动 | 中 | 第二阶段；按画质、编码、音轨组合判断，未知权限不写确定性会员结论 |
| F02 范围实时联动及隐藏控件清理 | 中 | 第一阶段；防抖、就地校验、每视频独立状态、提交前同步处理 |
| F03 下载中追加任务 | 中高 | 第二阶段；先做等待队列和独立解析通道，默认串行，允许配置 1–4 项并发 |
| F04 单项取消、暂停、整批入口 | 取消中高，续传高 | 第二阶段做单项取消；暂停队列与单文件暂停分别评估，本版纳入单会话暂停续传 |
| F05 状态语义色 | 低 | 第一阶段；三种主题/高对比/选中状态，文字和符号同时保留 |
| F06 失败原因与重试入口 | 低至中 | 第一阶段；状态短文本、原因入口；第二行排版按行高方案决定 |
| F07 悬停操作与高频快捷操作 | 低至中 | 第一阶段；悬停和键盘聚焦可发现，点击命中与多选范围明确 |
| F08 总进度、总速度、动态标题 | 中 | 第二阶段；先做任务结束进度，字节总进度另评估 |
| F09 简化详情及复制诊断 | 低 | 第一阶段；默认面向用户，技术诊断按白名单导出 |

| F11 表格文件预览 | 低至中 | 第一阶段；复用已有结构化事件，不改变执行时重新检查 |

| F14 忙碌设置的保存与生效提示 | 提示低，行为调整中 | 第一阶段澄清；推荐保存后对新任务生效，不能假称已有自动延迟应用 |

推荐依赖顺序：统一状态/错误/动作呈现 → 范围、预览、详情与设置 → 能力选择与布局 → 队列控制器 → 单项取消 → 总体反馈 → 可选暂停与其他扩展。F03 与 F04 可以在同一阶段交付，但不能通过多次并行调用现有 runner 绕过模型约束。

当前不纳入：跨重启任务历史/续传、限速、公开 JSONL/错误码协议、config 子命令、stdin、新平台、更新信任根迁移。单会话暂停续传、代理、命名模板和媒体任务并发已按维护者要求纳入；GUI 复制诊断不等于共用公开诊断协议全部完成。

## 3. 功能行为契约

以下为推荐验收契约。开发记录中标明采用或调整；冻结后，同一条契约的界面、共享模型、测试与用户文档必须一致。

### 3.1 F01：媒体能力与实际选择

- 按当前有效账号、输入代次和选集身份关联能力快照。登录/退出、凭据变化、链接/选集变化后失效；未知或未读取不能当作不可用。
- 联动画质、视频编码与音轨，不把 AVC/HEVC/AV1 的可用性独立于画质判断。低级别画质没有某编码，不代表该视频任何档位都没有该编码。
- 单选集显示“最高可用：1080P · AVC”等实际预测；多选集显示“各选集分别选择”及逐项结果，混合或未知能力不显示唯一确定档位。
- 单一已知范围可禁用不可获取组合；批量范围区分全部可用、部分可用、未知及全部不可用，不以一个当前视频禁用整批选项。已选项变为不可用时显示提示，不静默改变下载要求。
- 有明确权限依据才写“需登录 / 需大会员”；否则使用“当前不可获取”“该视频未提供”或“待确认”。不能把试看、DRM、地区/购买限制或解析缺失统一归为会员问题。新增权限原因字段时处理上游缺失和未知枚举。
- 复用或抽取 `build_plan` 的纯媒体选择逻辑，保持最高可用、编码偏好、降档、严格匹配和音轨规则一致。GUI 预测不得创建目录、下载媒体或固定签名 CDN 地址；执行与重试仍重新核验实际能力。

### 3.2 F02：范围输入实时联动

- 输入约 200 ms 防抖；仅更新当前视频的勾选，不在每次输入后弹出模态错误。非法/超范围输入保留上一次有效选择，红框配错误文字，高对比下仍可辨识。
- 推荐空输入表示该视频全选；链接指定 P 的初始选择仍遵守既有规则。手工勾选后显示“自定义选择”或准确范围，切换视频恢复该视频状态，避免沿用另一视频文本。
- 输入法组合输入期间不应用。点击下载、文件预览或“对所有视频使用此范围”时，先同步校验/应用未完成防抖，非法输入阻止提交并定位控件。
- 批量应用先逐视频校验；推荐任一超范围时整次不应用，列出失败视频及集数，避免部分静默成功。其他策略须在 D02 记录并有独立用例。
- 删除“应用”按钮和“范围须点击应用”说明，保留并改名批量按钮；避免批量应用逐个切换当前项触发范围串扰。
- 移除隐藏 `page_edit` 时迁移所有读取、初始化、摘要、回退和测试引用；真实勾选是提交来源，范围文本不成为第二套冲突选择状态。

### 3.3 F03：运行中提交与等待队列

- 推荐可在下载中打开草稿、解析并提交新批次；新批次立即显示等待状态，当前媒体任务继续执行，后续批次按提交顺序自动运行。追加不等于媒体任务同时下载。
- 每次提交固定来源、选集、quality/codec/audio、strict/overwrite、绝对目录和 FFmpeg 偏好。后续编辑表单或默认设置不改写已提交快照；相同 URL 不静默合并，重试保持任务 ID 与尝试关系。
- 设计纯 Python 队列控制器，将“接受提交”“等待”“运行”“完成”分开。可以扩展 Session，也可以增加显式调度层，但不能先把等待批次标为活动批次再让旧 `finish` 清掉它；不能只改按钮或把新来源追加到 runner 已截取的 tuple。
- 下载、草稿解析各有独立上下文/取消令牌与 worker 生命周期。旧输入、旧账号、已关闭草稿的迟到事件不能污染当前结果；Qt 模型只在 GUI 线程更新，锁内不调用外部回调。
- 关闭草稿只取消该草稿的解析；单项重试在下载中可入队，原参数/调整参数重试的差异清楚。预览保持只读，不登记成可执行任务。
- 退出、托盘、通知、更新安装必须考虑整个队列。默认不在退出/升级后恢复等待任务，不能静默丢弃；推荐有等待项时不自动安装更新，用户明确清空或取消后才能退出安装。其他策略在 D04 冻结。

### 3.4 F04：单项取消与暂停边界

- 提供任务级和来源/批次级取消作用域。来源取消包括其尚未结束的已发现任务及未发现部分；单项取消不能改变同来源兄弟任务或其他批次。
- 推荐“取消本批”只作用当前运行批次，等待批次保留；“取消全部等待及运行任务”是另一个明确动作。二级菜单可显示影响数量；确认频率在 D03 决定，不能把所有取消都强制弹窗。
- 等待任务取消无需网络请求；执行中显示“正在取消”，完成工作线程和 FFmpeg 清理后才进入终态。子令牌同时观察任务及批次/全局取消，局部异常不得触发现有批次 finally 取消全部。
- 重试建立新尝试并重新读取能力；每尝试一个终态，旧事件不能覆盖新尝试。文件已成功提交后完成状态优先于晚到取消；提交前取消保护既有文件并按现有规则清理临时目录。
- 单项操作传稳定 ID/attempt，不通过行号、当前选中项或标题猜测对象。菜单打开后对象状态变化时，执行前再次核验。
- “暂停队列”仅停止调度后续任务，当前任务继续，界面说明这一语义；不冒充单文件暂停。若纳入，暂停时不得自动完成批次或自动启动更新。
- 真正单文件暂停/续传独立设计：保留临时材料、Range/206/Content-Range 与资源一致性验证、地址过期重新解析、能力/身份变化处理、校验/合并阶段策略、恢复后字节和速度复位。当前每次 `wb` 下载且取消清理目录，禁止以取消后重试冒充续传。

### 3.5 F05/F06/F07：状态、原因与行内操作

- 完成绿色、失败红色、跳过/取消灰色，进行中按主题强调；颜色由统一主题适配生成，文字和符号仍独立表达结果。浅色、深色、高对比及选中/失焦行都检查可读性，不能硬编码黑底之外不可读的颜色。
- 状态列仅放状态，不拼接完整原因。保留已有 tooltip，增加“查看原因”详情入口；若显示第二行小字，调整委托/行高策略，不能继续假设所有行高度相同而截掉文本。
- 完成行提供“打开文件夹”，失败行提供“重试”；菜单在悬停或键盘聚焦/选中时可发现。扩展操作列宽、命中区域、tooltip 和键盘动作，保留右键与菜单键入口。
- 行内快捷动作只针对点击对象；多选批量操作仍走明确批量入口。等待队列未实现时，忙碌重试说明限制；实现后进入同一队列，不另起竞争 runner。
- 状态改变后同步刷新动作列和提示、禁用条件，避免图标留在已取消或已完成行。操作图标必须实际可点击，不能只绘制外观。
- 可继续扩展现有委托，Qt 支持通过 `editorEvent` 处理不启动编辑的鼠标事件。[Qt 委托接口](https://doc.qt.io/qt-6/qabstractitemdelegate.html)

### 3.6 F08：全局反馈与统计口径

- 推荐先提供“已结束 3/12 · 失败 1 · 4.2 MiB/s”及任务结束进度条。“已结束”包含完成/跳过/失败/取消，成功数单独显示，不能把失败称为完成下载。
- 推荐主窗口总体范围为当前运行与等待批次；结束后保留本轮摘要，开始新一轮重置。筛选和隐藏历史行不影响分母；重试按本轮尝试计数，不把旧失败再算一次。每批详情保留自己的不可变摘要。
- 发现尚未结束时显示“已发现 N 项，仍在读取”，不承诺最终分母；来源读取失败单列统计，不能伪造一个媒体任务补分母。追加改变分母时显示新增数量，不强制保持虚假的单调百分比。
- 所有任务身份已知后显示任务结束比例；传输、校验、合并、保存仍算未结束。不能用各行百分比直接平均成全批字节比例。
- 总速度取活动媒体传输的有效估算值之和，复用现有样本、停滞和重试规则；不含更新包或历史任务。校验/合并期间不显示旧网络速度；未知大小不影响可计算速度。
- 窗口标题/托盘提示使用同一快照，推荐“BiliX · 已结束 3/12 · 4.2 MiB/s”，结束后恢复版本标题或清晰结果；复用 250 ms tick 并限频，不能每个 chunk 重绘全树。
- 整批字节百分比和整批/后处理 ETA 不默认纳入，未执行流大小通常未知。[Qt 不确定进度条](https://doc.qt.io/qt-6/qprogressbar.html)可用于发现阶段，不等于已知总量。

### 3.7 F09：用户详情与诊断复制

- 默认显示标题/选集、状态、实际输出或计划路径、失败原因和建议动作；有适用操作时提供重试、打开目录、调整设置或重新登录入口。
- 尝试号、请求/原请求 ID、批次 ID、内部 error_code、FFmpeg 等技术字段集中进入折叠技术区或“复制诊断信息”；批次需要用户可理解的名称，不能默认仅显示短随机 ID。
- 诊断使用明确白名单，复用安全错误字段；禁止复制 Cookie、token、二维码、请求头、响应正文、签名 CDN 地址、异常局部变量或原始第三方异常。导出说明本地路径可能包含用户名，不自动上传诊断。
- GUI 诊断是本版局部能力，不冻结 CLI/JSONL 的公开诊断 schema。来源失败和尚无输出的任务也可查看原因。

### 3.8 F10：草稿布局与元数据

- “来源信息”和复制 JSON 移到结果树菜单或可发现的详情入口，兼顾键盘；选择动作和下载设置靠近结果，底部下载/预览按钮始终可达。
- 推荐下载设置分为目录一行、画质/选集一行，窄窗口允许重排；不把 700 px 宽度的全部设置硬挤为单行。不以增大最小窗口尺寸替代小屏适配，必要滚动保留。
- UP 主复用已有 owner，在缺失的番剧/影视元数据中显示合适占位，不要求新增冗余字段。
- 封面在 VideoInfo/解析器/public_dict 中增加可选字段，覆盖 UGC 与可获得的 PGC 形状；不猜测页面没有提供的封面。兼容已有模型构造、公开字典使用者与测试。
- 封面异步获取、限制并发/响应大小和图像解码尺寸，使用占位图和有界缓存；关闭/切换草稿后忽略迟到结果。远程图片不携带账号凭据，仅接受经过校验的支持来源地址，不把任意响应 URL 当可信请求目标。
- 封面加载失败不令解析失败、不阻止下载，性能验收包含 100/1000 项占位或缓存场景。加载策略、支持来源和缓存边界在实现记录中说明。

### 3.9 F11：结构化文件预览

- 使用“文件名 / 目标路径 / 结果”表格，直接消费 preview 事件；新建、跳过、替换、阻止提供语义色和文字。结果完整含“跳过：已存在，未校验”。
- 推荐阻止优先、替换其次，其余保持来源/选集顺序，显示原始来源序号；可恢复原始排序。保留重复目标、降档警告、选择结果和原因入口。
- 无法生成路径的来源/选流错误仍生成阻止行，路径为空有明确说明，不能因没有 output 而漏项。汇总与行数遵守来源/任务区分。
- 预览不创建执行记录、不下载、不覆盖；结果为检查时预测。执行仍复查冲突和目标身份，预览后外部创建/删除文件不绕过既有保护。

### 3.10 F12：解析失败定位与重试

- 失败行显示红色图标加“解析失败”，时长不再承载完整错误；tooltip/详情提供完整安全原因和建议，失败项保持不可提交。
- 行内“重试”与顶部“重试失败项”共用可接收指定来源集合的入口；单项重试不能顺带重读全部成功项或清掉它们的勾选。
- 重试使用输入/账号代次及来源身份保护；编辑链接、关闭草稿或重复点击不让旧响应增加错误计数或生成重复子项。忙碌条件与独立解析通道一致。

### 3.11 F13：设置组织与扩展边界

- 常规页拆成“下载 / 外观 / 系统集成”，托盘能力说明贴近对应控件；保留环境变量覆盖说明、配置目录入口及取消/应用语义。
- 默认画质/编码可先沿用 GUI 偏好；推荐媒体记忆开启且有有效上次值时使用上次值，否则使用显式默认；首次仍为最高可用/自动编码。不得静默改变 CLI 默认。覆盖同名文件仍不记忆或自动恢复。
- 命名模板需要允许字段白名单、非法字符/长度处理、身份后缀和同名冲突规则，规划/预览/下载共用实现，不能仅拼接 GUI 字符串。
- 代理需明确是否共用 CLI，覆盖解析/API、登录、短链、封面、媒体及适用的更新请求；保留短链不发账号凭据和更新验签规则，说明环境代理优先级。代理认证信息不进入诊断和发布材料。
- 同时下载数等队列/取消稳定后再开放。现有单视频音视频两流并行不等于两个媒体任务并发；新增并发还需客户端/FFmpeg 资源边界、全队列同路径协调和取消隔离。
- 命名模板、代理、并发不能作为第一阶段“设置分组”的隐含交付；纳入时增加模型/配置兼容和专门验收。

### 3.12 F14：保存与生效时间

- 推荐允许忙碌时保存业务默认与界面偏好：目录/FFmpeg/默认媒体选择对后续新提交任务生效，已提交的运行和等待任务保留快照；界面偏好保存成功后立即生效。
- “下载结束后生效”仅用于实际具有延迟应用行为的项目。推荐方案文案为“对新任务生效”；不能让用户误以为已排队任务也会更新。
- 如果采用延迟到空闲方案，必须有待应用值、持久化/取消规则、自动应用触发和失败反馈；再次编辑不能悄悄覆盖待应用值，退出行为须明确。
- 如果保持现有忙碌禁用，则标注“当前操作结束后可修改”，不宣称保存成功或自动延迟。统一 `_set_busy`、按钮状态和 `_save_settings`，GUI-only 偏好允许应用的现有测试路径也要在真实界面可操作。
- config.toml 与 gui.ini 没有跨文件事务，准确说明哪部分已保存/未保存，失败不能只给五秒状态栏消息；环境覆盖和损坏配置处理沿用既有保护。

## 8. 构建、部署、发布与恢复

### 8.1 发布前检查与构建

1. 冻结功能范围、解决影响身份/取消/文件事务/凭据保护的失败；记录接受的未验证范围、负责人及补测计划，不用旧版绿色结果自动放行。
2. 从同一最终产品源码构建 Python wheel/sdist、Windows CLI ZIP、GUI portable/installer 及 Linux deb，收集对应源码、许可和工具链材料。Windows/Linux 命令及环境按 GUI 构建指南执行，源码或构建输入变化后重建受影响产物。
3. 沿用 `scripts/assemble_gui_release.py`、`scripts/assemble_release.py` 生成最终清单、大小/SHA256；再用 validate 的 release-dir 只读检查，不用集合脚本改写公开文件证明一致。
4. 复核工作树/历史凭据检查及归档内容，诊断/测试材料不得包含真实 token、Cookie、签名 URL、二维码、代理认证或部署私钥。证据放忽略目录，版本记录只保留脱敏结论。
5. 验收 1.7.7 → 候选的安装/更新/重装/卸载及数据保留；队列为会话能力，不承诺升级后恢复。产品界面必须在等待项存在时正确协调更新，不能要求用户凭记忆避开数据丢失。

### 8.2 签名和渠道部署

1. 在新 staging 中签名最终 GUI 更新材料，沿用既有 Ed25519/APT 信任根与稳定安装身份；序号必须大于部署时各渠道已发布值，不能硬编码沿用 1.7.7 序号。签名工具、密钥位置和验证按更新部署指南，本文不创建或上传密钥。
2. 准备 GitHub 草稿、版本化官网镜像、PyPI wheel/sdist、签名 APT 快照及 `site/bilix.html`/发行说明。版本化资产上传并核验完整后，才让任一 stable/latest 入口指向该版本；以部署工具实际切换行为协调两渠道窗口。
3. APT 先部署 pool/by-hash，再部署其余索引，最后切换签名 Release/InRelease；保留旧快照和包。项目页面源码单独部署，代码/标签推送、包上传不会自动更新网页。
   服务器常规部署统一使用 `bilix@djhx.site` 的专用 SSH 密钥：安装包/源码、更新元数据、APT 和官网首页均包含在内。2026-10-12 已补齐站点根目录和首页所有权，后续不再使用 koril/sudo 部署网页；官网通过 `scripts/deploy_site.py` 校验哈希、备份并原子替换。仅服务器配置维护需要管理员，详见 [部署账号说明](application-update-plan.md#113-当前统一部署账号与官网权限2026-10-12)。

5. 执行真实外部上传/安装/服务切换前，按维护者已有授权与发布流程处理。维护者现已明确授权本版开发、测试及部署发布，可在具体候选和证据就绪后执行提交、推送与发布；不把待执行步骤写成已完成。

### 8.3 发布后核验与失败恢复

- GitHub、官网、PyPI、APT、实际维护的其他镜像和网站分别记录状态。完整回下载核对大小/SHA256、签名及隔离安装；若仅核对服务器字节或 HTTP 首尾范围，必须明确写抽样范围，不能称完整回下载通过。
- 旧客户端检查可发现候选、当前版本不再提示同版更新；测试 GitHub 优先/官网备用、最终安装启动和普通用户身份。签名/APT/安装事务未改时按影响抽查，队列与更新互斥必须重新验证。
- 核对网页和 README 实际发布版本、各系统文件名、配置说明、新增入口及已接受限制，再填写 1.7.8 验收记录的发布授权/时间与结论。
- 可用性问题优先停止推广入口并保留已公开文件/日志；不要把旧签名序号当作可靠的远程降级方案。portable、installer、APT 的人工恢复沿用各自指南，安装器不承诺完整自动回滚，旧配置兼容需实测。
- 已公开产物发现产品问题时使用新修复版本；不得重包覆盖同版本文件、标签或 PyPI。恢复动作与功能修复分别记录，避免把撤下入口等同于客户端已修复。
