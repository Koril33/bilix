# 1.8.0 下载内容与独立文件设计

日期：2026-10-14。维护者已选择研究方案一，并授权开发、精简虚拟机测试及按既有流程发布。当前实施与发布结果见 [validation-1.8.0.md](validation-1.8.0.md)。

## 范围

新建下载中增加始终可见的“下载方式”：完整视频（含声音，默认）、仅音频、仅视频（无声音）、音频与视频分别保存、仅封面。前四种可勾选“同时保存封面”。沿用选集、保存目录、文件预览和更多选项，不新增导出向导。

只请求需要的媒体流。AAC 独立保存为 M4A；FLAC/Dolby 保持源编码并保存为仅含音轨的 MP4，预览明确格式。视频独立保存为无声 MP4。继续使用现有 FFmpeg 包扫描、时长检查和流复制，不转码、不增加 MP3 编码器、不把临时 M4S 当作用户输出。完整视频保留既有命名和合并校验行为。

仅音频隐藏画质、视频编码和严格匹配；仅视频隐藏音轨；仅封面隐藏媒体参数并按来源保存。切换只影响新提交，队列及原参数重试保留快照。记住媒体选项时同时记住下载方式与附带封面，覆盖选项继续不跨会话记忆。

## 文件与失败契约

- 文件预览列出每个输出及覆盖/跳过决策；身份后缀避免不同下载方式互相覆盖。
- 独立音视频逐文件下载、校验、提交；一项失败不丢弃另一项成功结果。任务标记失败并注明部分完成，支持默认重试失败文件；调整参数重试按新参数生成计划。
- 附带封面失败单独显示，成功媒体保留；仅封面失败就是任务失败。任务详情列出全部结果并提供逐文件打开入口，多文件任务双击打开目录。
- 默认跳过已有普通文件且注明未校验；替换在新文件校验成功后进行。取消保留已提交结果，清理当前未提交临时材料；普通错误保留排查材料。
- 普通投稿多 P 只为本来源保存一次投稿封面；独立音视频仍按所选 CID 下载。番剧使用实际返回的剧集或系列封面，不承诺接口没有提供的图片。
- 封面仅请求允许的 Bilibili 图片 CDN、使用 HTTPS、不附账号凭据、不跟随任意重定向；验证图片类型并使用实际扩展名。封面元数据可用时，不以正片播放权限作为封面导出的前置条件。

## 实施与精简验证

共享内核支持模式、多个计划路径及逐文件结果；CLI 提供 `--mode merged|audio|video|separate|cover` 与 `--cover`，原命令默认行为保持一致。GUI 采用方案一，复用现有任务筛选、失败重试和文件预览。

本版不改工具链、安装器和更新协议。按维护者要求只做一轮本地完整 GUI 回归（含 CLI/共享内核）、最低 Python wheel 入口验证、新模式的有意义测试，以及代表性 Windows/Linux VM 的启动与功能简测；不重复四发行版完整桌面/IME/安装生命周期矩阵。未执行范围如实登记。

发布继续使用 [releasing.md](releasing.md)：同源八项产物、许可/源码、集合哈希、现有签名密钥和递增正式序号，GitHub/Gitea、PyPI、服务器更新镜像、APT 与官网，最后公开回验。精简功能测试不省略发布文件完整性和签名检查。
