# GUI 易用性建议实施评估

> 历史设计/评审：保留当版基线、建议和决策。当前行为见 [使用文档](README.md#当前使用与开发)，未完成功能见 [backlog.md](backlog.md)，缺陷与流程问题见 [workflow-issues.md](workflow-issues.md)。构建、测试与发布从 [handoff.md](handoff.md) 进入，不直接执行下方旧版命令。

评估日期：2026-10-10。对象：[gui-usability-review.md](gui-usability-review.md)，对照当前 1.7.2 源码。

## 结论

建议文档抓住了主要问题：首屏控件太多、配置与历史争夺空间、选集离输入太远、重试动作的对象不明确。推荐采用“添加下载区 + 下载列表 + 按需详情”的方向，继续使用 PySide6 和现有任务内核即可，不需要换 GUI 框架或重写下载流程。

大部分呈现调整容易或中等难度；完整目标界面属于一次中等规模重构。运行中追加、单项取消/移除、可靠的速度与剩余时间不是简单界面改动。文档对几个“快速收益”项目的工作量估计偏乐观，不能将整份方案当作小补丁。

本次只实施 README / 项目页面图标与 favicon，并完成评估，没有实施 GUI 改版，也没有改变会员或非会员的下载行为。

## 核查范围与补充事实

原文基于 1.7.1，只阅读了 `app.py` 前约 1000 行，未阅读 worker、任务模型和 GUI 测试。1.7.2 的 GUI 变化主要是图标，原文的布局判断仍适用。本次补读了这些部分：

- [app.py](../src/djhx_bilix/gui/app.py)：界面、输入与选集、重试、操作线程、完整事件处理、完成/取消和登录状态。
- [worker.py](../src/djhx_bilix/gui/worker.py)、[tasks.py](../src/djhx_bilix/tasks.py)：串行操作约束、任务/来源/尝试关系、取消作用域、进度事件。
- [models.py](../src/djhx_bilix/models.py)、[client.py](../src/djhx_bilix/bilibili/client.py)、[planner.py](../src/djhx_bilix/planner.py)：安全元数据、媒体可用性与严格匹配语义。
- [GUI 测试](../tests/gui/test_tasks_gui.py)、[基础 GUI 测试](../tests/gui/test_gui.py)：旧解析结果失效、快照重试、只读预览、选集及配置覆盖的现有约束。

另做了两个离线窗口尺寸的检查（940×760、760×590）。使用 Qt offscreen、Microsoft YaHei 9pt，下载页分别有 316 和 486 像素的纵向滚动范围；小窗口首屏看不到底部进度与记录操作。这支持 A5 的判断，但不是原生 Windows / Linux 或多 DPI 验收。空会话中，只有“重试全部失败”禁用，选中重试、全部取消重试和清理按钮仍启用，B4 判断成立。

需要修正或细化的事实：

1. **并非只有全局进度。** `_on_event` 已在任务行显示视频/音频百分比，未知总量时显示已传字节；缺少的是速度、传输 ETA 和更直观的阶段展示。B6 可以先改呈现，不必先重写进度来源。
2. **本地有凭据不等于已登录。** 启动时离线检查只知道凭据存在、格式是否有效，无法确认服务端有效性或会员状态。账号徽标应区分“未保存凭据 / 已保存、未验证 / 已验证登录 / 已失效”，不能启动就显示“已登录”。
3. **可用画质已有数据，但不是整批权限保证。** `public_dict()` 已提供 `available_streams` 和 `advertised_qualities`，两者不能混为一谈。多 P / 番剧的首个已读取视频不能代表所有选集，更不能保证登录后必有某一画质。下载执行时仍需重新验证实际媒体和权限。
4. **界面文字仍承载行为约束。** 严格匹配同时约束指定画质和编码；不能简化成只提画质。跳过现有文件不等于该文件已校验，清除记录也不等于删除文件。

## 各项设计的难度

“容易”指局部呈现或现有动作重用；“中等”指跨控件状态、组件拆分或 GUI 数据适配；“较高”指操作控制器/任务契约改变。不是工期承诺。

| 建议 | 难度 | 实施判断 |
|---|---|---|
| A1：添加区、下载列表、详情分开 | 中等 | 固定简洁添加区，列表占剩余空间，详情用对话框或可折叠面板。先去掉整页滚动，而非仅减小窗口最小尺寸。 |
| A2：取消内部三标签，统一列表 | 中等偏高 | 可只做 GUI 适配层；保留来源读取失败行、每个选集的任务行、重试历史与批次归属。输入预览卡和下载历史应是不同视图，不能直接共享一套可编辑条目。 |
| A3 / B4：动作靠近对象、重试下拉 | 容易到中等 | 默认按原参数重试，当前参数重试保留确认。先做选中项工具栏和右键菜单，比给每行装多个按钮更省空间、也更利于长列表性能。 |
| A4：预览对话框、详情独立 | 中等 | 复用 `run_preview`，按文件显示新建、跳过、替换、阻止等结果。预览仍是读取时刻快照；不保证执行结果。保留明显的入口，不必藏得太深。 |
| A5：减少嵌套滚动 | 容易缓解，中等彻底解决 | 默认折叠详情可缓解；固定输入区 + 独立列表滚动才解决根本问题。展开选集/更多选项也必须考虑小窗口。 |
| A6：账号/设置/诊断合并 | 中等 | 对话框可复用现有字段、QR 登录和诊断动作。运行中允许查看设置，与运行中允许启动登录/诊断是两件事，后者受单操作线程约束。 |
| B1：下载时追加、单项取消/移除 | 较高 | `Session._begin()` 拒绝第二个活动批次，`run_batch()` 使用批次任务集合和一个取消令牌。仅解锁输入框无效；需要队列、独立取消作用域与线程安全控制器。 |
| B2：自动解析与结果卡 | 中等偏高 | 复用 `run_info`，但需要防抖、过期结果丢弃、重复输入处理、账户变更失效和取消。保留手动解析/直接下载途径，避免网络解析成为额外的强制等待。 |
| B3：只使修改的链接信息失效 | 中等 | 当前缓存按行索引保存。插入、排序、重复链接、`?p=` 或 `ep` 变化都会影响映射；必须保留选集状态和 generation 防过期机制，不能只比较字符串列表。 |
| B5：双击打开文件，下载时可开目录 | 容易 | 复用文件打开/路径检查。仅在有可打开输出时打开文件，失败/进行中行双击查看详情；现有文件消失时给出明确提示。 |
| B6：阶段、速度、剩余时间 | 容易到中等，完整契约中等偏高 | 当前行进度可直接改善。GUI 可试作速率显示，但可靠功能应覆盖重试/字节归零/未知总量，并明确 ETA 只指传输，不含校验与合并。 |
| B7：一个目录入口、记住偏好 | 中等 | 先解释“本次目录”和默认值，可立即减少困惑。记住目录/画质/窗口状态应放独立 GUI 偏好；不能覆盖 CLI 配置或忽略环境变量优先级。 |
| B8：主界面账号徽标 | 容易 | 展示已有离线/在线状态；账号变更后解析信息失效。可提示“此视频当前可获取画质有限”，不承诺登录或会员必然解锁。 |
| B9：快捷键、拖放、剪贴板 | 快捷键容易，完整拖放中等 | Ctrl+Enter 最适合先做，保留 Tab 和输入法组合态行为。文本文件拖放涉及多文件、编码、混合内容和行号错误；建议先加主动“粘贴”按钮，自动读剪贴板提示可后置。 |
| C1：术语与 ID 收进技术详情 | 容易到中等 | 下载列表用视频、选集、失败原因；详情仍保留身份、参数、尝试与安全诊断导出，便于定位问题。 |
| C2：隐藏画质数字、动态画质列表 | 数字容易，动态中等 | 保留最高可用默认。单个视频可按已读取流提示；多链接用“按各视频可用情况下载”及逐项提示，不能拿首个视频限制全部链接。 |
| C3：编码/音频/严格匹配说明 | 容易 | 加短说明，保持 auto / AAC 等现有默认。兼容性预设可后置；HEVC/AV1 文件大小取决于源流，不能承诺一定更小。 |
| C4：更多选项展开、非默认摘要 | 容易 | 可以用展开按钮；折叠时仍显式提示覆盖、严格匹配和自定义选集，不将这些状态隐藏在泛泛的“已设置”徽标里。 |
| C5：时长、全选/全不选/反选 | 容易 | 重用现有勾选逻辑，明确作用于当前视频；全不选时仍禁止开始该项。长选集搜索是额外的中等工作。 |
| C6：主按钮、空态、留白 | 容易 | 强调下载按钮，取消保持清晰作用域。主窗使用 Ctrl+Enter；不把多行输入中的普通 Enter 改为下载。 |
| C7：设置来源说明按需显示 | 容易 | 普通状态简洁；环境变量正在覆盖时，应在对应字段旁说明“保存后仍被覆盖”，不能全部藏进诊断页。 |
| D1：拆分 MainWindow | 中等 | 随改版逐步拆成输入/选集、任务列表、详情、设置组件，通过信号交互。无需先做一次大规模纯重构，避免同时搬动所有逻辑。 |
| D2：国际化 | 容易起步，完整翻译另排 | 目前中文界面可后置；不作为本次易用性改版前置。 |

PySide6 已有实现这些常规交互的控件。例如“重试 + 下拉选项”可用 [QToolButton 的 MenuButtonPopup](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QToolButton.html)；主要成本在 BiliX 自己的状态衔接，不在控件是否支持。

## 不宜直接照搬的设计

- **不能删除来源读取失败的可见入口。** 有些链接尚未发现选集就失败，此时没有任务行。统一列表也必须能展示和重新读取它；同时保留重读与任务重试的区别。
- **不能按 URL 把所有历史合成一个可修改对象。** 同一视频可重复下载、不同选集/目录/质量可共存。显示上可分组，行为仍以 request / task / attempt ID 和实际快照为准。
- **不建议现在增加“等待当前批次结束后自动下载”的临时队列。** 这仍要明确保存哪个参数快照、取消范围、退出行为和错误处理，是队列功能的一部分，容易形成两套实现。
- **普通选集勾选应是唯一明确的当前结果。** 范围输入可作为“应用到勾选”的工具，而非一个暗中覆盖勾选的第二状态。保留链接指定 P/EP 的默认语义，不能默认把显式单 P 改成全部选集。
- **不用单纯的“取消”隐藏作用域。** 可统一为“取消本批下载”等简洁文字，并保留取消中反馈；只有单项取消真正实现后才在每行显示取消按钮。
- **清理用“清除记录”，删除输出文件是另一项操作。** 完成与“已存在，跳过未校验”应继续区分；原文只列 All / Active / Failed / Done，也要补充等待、取消等状态。
- **状态栏剩余磁盘空间是附加功能。** 需要按实际输出磁盘获取，处理网络目录/不存在目录与刷新，收益不如首屏与选集调整，建议后置。

## 推荐推进顺序

### 第一步：局部改善，不动下载内核

主按钮与留白、更多选项展开、隐藏画质数字、格式化时长、全选/全不选/反选、按状态启用动作、完成项双击打开文件、主界面账号提示、简洁文案及 Ctrl+Enter。目录来源覆盖和严格/覆盖摘要继续清晰可见。

这一步风险低，但不要把 B3 的缓存迁移、自动解析或动态多视频画质硬塞进“小改动”。

### 第二步：解决主要布局问题

改为短添加区 + 占据剩余空间的下载列表；输入附近显示解析/选集卡；详情与文件预览独立；账号/设置/诊断收进设置入口。逐步抽组件，用 GUI 适配层统一来源与选集显示，保留底层身份和快照。

先保留主动“解析链接”，布局和选集稳定后再加入自动解析及缓存复用。这样每一步都可单独评审，也能避免一次改变页面结构、网络触发时机与任务行为。

### 第三步：任务控制与持久偏好

运行中追加、单项取消、速度/传输 ETA 和偏好存储按原有 B 功能规划实施。1.7.2 已发布；[既有评审与排期](cli-gui-ux-review.md)已将 B-01 至 B-07 顺延到后续功能版，版本待定。本评估不重新指定版本，也不改变 B 功能版整体交付约束。

## 验证范围建议

当前文档与页面图标改动只检查资源一致、README 图片路径、桌面/手机布局与 favicon 即可，不需要重跑下载矩阵。本次已在 Chrome 验证 1366 / 390 / 320 像素宽度：内嵌图标及 favicon 与应用 SVG 一致，无页面横向溢出，下载按钮目标保持正确。

后续 GUI 局部改善复用现有测试，围绕真正改变的交互做少量检查：选集与链接默认、原参数/当前参数重试、输入法与快捷键、动作启用状态、小窗口。缓存/自动解析另外验证旧结果不会覆盖新输入或新账号；列表合并验证来源失败仍可重读且任务快照不变。只有实际改动共享任务内核时，再扩大下载/取消验证范围。

无需为了首轮文案与排版改动重新完成全平台下载测试；较大布局发布前仍需针对 Windows/Linux、小窗口和 DPI 做必要的人工检查。offscreen 布局观察不能替代原生交互检查。
