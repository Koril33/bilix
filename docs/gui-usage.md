# BiliX 图形界面使用说明

图形版使用与 `blx` 相同的下载内核和账号凭据，面向 Windows 与 Ubuntu/Debian 桌面。源代码与 CLI 在同一仓库；两种入口可以并存。GUI 使用 Qt Widgets，安装的系统不需要另行安装 Qt。

从 1.6.0 起可安装 GUI 发行包，也可在源码目录运行：

```shell
uv sync --locked --extra gui --group gui-test
uv run --locked --extra gui bilix-gui
```

也可以在已安装 GUI 依赖的环境中运行 `python -m djhx_bilix.gui`。面向最终用户的绿色版、Windows 安装器和 Linux deb 的构建与安装方式见[GUI 构建与发行](gui-build-and-release.md)；发行文件应从项目发行页取得并核对哈希。PyPI 安装时使用 `pip install 'djhx-bilix[gui]'` 或 `uv tool install 'djhx-bilix[gui]'`，随后运行 `bilix-gui`。仅安装 CLI 包不会安装 Qt。

## 首次使用

1. 点击“新建下载”，粘贴链接/BV 号；支持拖入链接或 UTF-8 文本列表，也可用文件菜单导入。输入稳定约 500ms 后自动识别，中文输入法组合态期间等待输入完成。
2. 在同一对话框选择选集、保存目录与画质；默认最高可用、AAC、不覆盖。多 P 默认全部，`?p=` 默认指定集；各来源可单独勾选、应用范围或整体取消。部分失败会明确显示未加入下载，可重试失败项。
3. “更多选项”展开编码、音频格式、严格匹配和覆盖，收起时仍显示非默认项。输入或凭据变化使旧结果失效，重新识别完成后才可提交。
4. “文件预览”在只读窗口显示路径与冲突；实际下载重新检查。点击“下载”或 Ctrl+Enter 提交，Enter 在链接框内换行。关闭草稿保留本次会话输入，不取消已提交下载。
5. 主窗口提供全部、进行中、完成/跳过、失败、已取消筛选。视频和音频分别显示传输进度，100% 后仍有校验、合并、保存；底部取消以当前操作或下载批次为单位。
6. 下载期间可打开下一份草稿，但识别、预览和提交须等待当前操作结束，不支持运行中追加任务。通过更多操作、选中行“⋯”、右键或 Shift+F10 重试、打开文件/目录或查看详情；清除只清记录，不删文件。
7. 启动有合法 token 时自动验证账号，账号入口可扫码/手动重新验证/退出。待验证不等于登录成功，网络失败保留凭据；外部 CLI 修改 token 后重新打开草稿/账号页会检查变化。
8. 最小化默认隐藏到托盘，菜单恢复原窗口；没有托盘时普通最小化。标题栏关闭、Alt+F4 与菜单退出都真正退出，下载中先确认取消并等待线程结束。每个真实下载批次结束最多通知一次，取消不发完成通知；系统抑制通知时仍可查看列表和结束摘要。

不登录也可以查询和下载公开可访问的视频。会员或购买内容取决于账号实际权限；界面不会绕过付费、试看或 DRM。播放接口标记 DRM 的媒体会明确拒绝下载。

## 下载选项

| 界面选项 | 对应 CLI | 行为 |
| --- | --- | --- |
| 链接输入、导入列表 | `blx download URL…`、`--file` | 批量加入任务；列表文件支持 UTF-8 BOM、空行及 `#` 注释 |
| 清晰度 | `--quality` | 自动选择，或设定最高目标画质；不可获取时默认降到较低可用清晰度 |
| 编码 | `--codec` | 自动、AVC、HEVC、AV1；可用编码依具体视频与账号而定 |
| 音轨 | `--audio` | AAC、FLAC、Dolby、best；指定音轨不可获取时任务失败 |
| 选集 | `--page` | 例如 `1,3,5-7`；不指定时，多 P 默认全部，含 `?p=2` 的链接默认仅 P2 |
| 严格匹配 | `--strict` | 指定清晰度或编码不可获取时失败，而非降级 |
| 覆盖同名文件 | `--overwrite` | 默认跳过已有文件；勾选后仅在新文件下载、校验、合并成功后替换 |
| 预览计划 | `--dry-run` | 查询与计算计划，不下载媒体 |

一次启动下载会把当时的选项保存为该任务的快照。任务开始后修改输入或设置不会改变已排队任务；如需另一组选项，请另行开始。界面串行处理各视频任务，单个视频的音视频流并行下载；不提供暂停或断点续传。

任务列表在本次窗口会话内跨批次保留，退出后不持久化。“重试选中项（原参数）”使用所选任务**最新一次失败/取消尝试**的参数；“调整参数后重试…”打开固定身份的独立编辑上下文，显示原参数，调整后再明确提交；不会读取另一份草稿的参数。只重试对应选集，不重新下载已成功任务；同一批重试可以保留不同任务各自的参数。失败和取消的批量入口分开。来源未能读取时，在下载列表选择该读取失败行再重新读取；它产生关联的新读取记录，不伪造媒体任务。

每个任务使用稳定身份和 CID/EP 校验。重试重新获取当前权限和媒体；来源选集身份变化时拒绝重试，需重新读取创建新任务。旧尝试和已结束批次汇总保留。“清除已完成 / 跳过记录”及“清除失败 / 取消记录”仅在空闲时可用，只清会话显示记录，不删除任何输出或临时文件。

一次只运行一个后台操作，须等待当前批次结束才开始新批或重试；没有运行中追加、单项取消、速度/剩余时间、暂停续传或应用内更新。后续范围见[版本规划](roadmap.md)。

“取消”会请求后台任务停止。网络请求可能需要等待当前请求超时，FFmpeg 处理也会被中止；正在写入的临时结果不会作为完成文件提交。已完成的任务和原有目标文件不受影响。普通失败时保留 `.bilix-*` 临时目录用于排错；确认不再需要后可手动删除。界面不会自动把临时目录当作可续传文件。

正常业务失败保留临时材料；显式取消会尝试清理本次临时目录，权限或文件占用时仍可能残留。下载运行中关闭主窗口会询问是否停止本批并退出，也可返回继续；读取操作退出直接协作取消，均等待线程停止。空闲退出不询问。本版验证范围见[1.7.4 验收记录](validation-1.7.4.md)。

## 账号、设置与诊断

启动先显示窗口并检查本地凭据，合法 token 自动安排一次账号验证；无凭据或格式错误不发送查询。账号入口的“重新验证账号”可手动刷新，网络失败保留待验证状态，不判定为过期。CLI 的 `blx auth login/status/logout` 与 GUI 共用用户配置目录，退出登录会删除本地凭据。不要在截图、日志或问题报告中公开二维码、Cookie、完整签名媒体地址或 `token.txt`。

“设置”页编辑文件中的默认下载目录和 FFmpeg 路径，存在环境覆盖时在下方提示。保存后重新加载环境覆盖；未手动修改的本批目录跟随生效默认值，手动修改的目录保留。路径字段保存只校验格式，不证明程序可运行。设置写入用户配置目录的 `config.toml`；环境变量 `BILIX_DOWNLOAD_DIR` 与 `BILIX_FFMPEG` 的优先级高于配置文件，`BILIX_CONFIG_DIR` 可改变配置目录。Windows 发行包使用随包提供的 FFmpeg；Linux deb 将系统 `ffmpeg` 声明为依赖，也可在设置中指定其他完整路径。可在设置的“关于与诊断”区检查实际使用的 FFmpeg 路径与版本，它不会执行网络登录或下载。

CLI 仍适合脚本、JSON 信息导出、shell 补全和批处理退出码；GUI 不替代这些终端接口。当前 GUI 没有应用内自动升级。升级 GUI 时从同一发行渠道取得新文件：绿色版关闭程序后替换 EXE，Windows 安装版运行新安装器，deb 用包管理器安装较新版本；用户配置与下载目录独立于程序安装目录。

## 常见问题

| 提示 | 检查方法 |
| --- | --- |
| 无法生成二维码或查询信息 | 检查网络、代理与 Bilibili 服务状态；稍后重试 |
| 账号失效或只能获取试看 | 在账号页查看状态并重新扫码，确认账号会员/购买权限 |
| 指定画质、编码或音轨不可用 | 查看信息中的实际可用流，调整选项；不要求精确匹配时关闭严格匹配 |
| 找不到 FFmpeg | 在诊断页核对路径；Linux 安装 FFmpeg 或在设置中指定完整路径 |
| 已有同名文件被跳过 | 核对输出目录；确定需要重新下载时启用“覆盖同名文件” |
| DRM 保护 | 使用平台官方客户端播放；BiliX 不提供 DRM 解密 |

命令行的完整参数、账号语义与下载校验细节分别见[使用说明](usage.md)、[账号说明](accounts.md)和[架构说明](architecture.md)。

## GUI 偏好与诊断

设置采用“确定 / 取消 / 应用”。取消仅丢弃尚未应用的编辑，已完成的扫码/退出登录不会回滚。下载目录和 FFmpeg 仍保存到与 CLI 共用的 `config.toml`，环境变量优先；窗口位置/列宽、上次画质/编码/音频、严格匹配及托盘/通知开关单独保存到配置目录的 `gui.ini`。GUI 偏好不保存 token、草稿或任务历史，覆盖同名文件在新会话始终关闭。

帮助菜单的“复制诊断信息…”先显示版本、平台和安全统计摘要，复制不包含完整路径、昵称、标题、媒体 URL 或凭据。完整本地 FFmpeg/配置检查仍在关于与诊断页。
