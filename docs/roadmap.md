# 下一版本建议（CLI 与 GUI）

建议下一功能版使用 **1.7.0**，继续统一产品/内核版本，同仓库发布 CLI 与 GUI。以下为基于 1.6.0 实际代码及[复核结果](validation-1.6.0.md)的规划，尚未实现，也不构成发布时间承诺。若先处理安装器等可靠性问题，可单独出 1.6.1，避免让缺陷修复等待完整功能版。

## 优先级与推荐范围

| 优先级 | 领域 | 建议变化 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 安装/升级 | Windows 比较已安装稳定版本并拒绝降级；以 1.6.0 测真正升级，验证失败恢复和数据保留 | 旧→新成功，新→旧拒绝；用户配置/下载哈希不变 |
| P0 | 补齐真实业务验收 | 受控账号扫码/过期/取消、普通权限/会员、实际多 P 和失败项重试；CLI/GUI 同计划/结果 | 无秘密进入日志，权限判断一致，输出可校验 |
| P0 | 平台体验与测试 | Linux IME、完整 Wayland、DPI/小屏/键盘；3.12/3.13 安装矩阵；固定镜像证据 | 按稳定用例 ID 填写结果/例外，不把启动当交互通过 |
| P1 | GUI 任务体验 | 增加下载速度、剩余时间、阶段解释；失败/取消/完成可筛选，单项重试/移除、运行中追加队列 | 总大小未知不编造 ETA；操作不影响别的任务，终态只产生一次 |
| P1 | GUI 信息与选集 | 展示标题/封面/可获取媒体；可视勾选多 P；高级编码/音轨折叠，预览实际结果 | 有效选项来自当前视频/账号，strict/降级规则与 CLI 一致 |
| P1 | CLI 自动化 | 增加可选 JSON Lines 任务事件与最终汇总、稳定错误分类；保留当前人类输出和退出码 | stdout 机器协议与 stderr 提示分离，批量部分失败准确，无签名 URL |
| P1 | 共用诊断 | 可脱敏导出的诊断，临时目录列表/清理预览、现有文件检查命令 | 不导出账号/二维码/秘密；清理须限定归属，不删除有效输出 |
| P1 | GUI 易用性 | 保存窗口/常用选项、快捷键、系统主题、高 DPI/小屏布局、关于/版本/许可入口 | GUI 偏好独立于业务配置，键盘全流程可达，重启恢复有效 |
| P2 | 下载恢复 | 经设计的 Range 续传与崩溃恢复，GUI 暂停/恢复与 CLI 恢复入口 | 校验远端身份、长度和范围；过期 URL 重新解析，坏分片不能提交 |
| P2 | 任务持久化/并发 | 共用任务 ID、可控并发上限、持久队列与历史，重启标记中断并可恢复 | 音视频连接数有界；并发提交安全；迁移和中断恢复回归 |
| P2 | 升级与平台扩展 | 先“检查更新/打开发行页”；后续验证签名更新清单或 APT 源；Windows 11 优先 | 源离线仍可用；不覆盖运行中程序，不把普通 SHA256 当真实性签名 |

1.7.0 推荐先交付 P0，加上速度/ETA、可视选集、单项重试、CLI 结构化事件及共用诊断。任务持久化与并发先做架构设计，续传/自动更新独立排期；否则难以同时完成故障和平台验证。

## 共用内核先行

CLI 与 GUI 应复用带任务 ID、阶段、字节、速率、时间和最终结果的纯 Python 事件模型。错误分类提供稳定 code 与可展示消息，第三方原始异常继续限制在安全边界内。CLI 机器输出和 Qt 信号分别适配，界面不解析 Rich 文本，也不复制 API/下载逻辑。

新增并发时区分视频任务与两路流的连接预算，先保证取消某项只影响该项，再开放用户上限。避免在持锁时调用界面/用户回调。长期保存的任务只能存规范化源地址、选集、选项和目标信息，不存 Cookie、二维码 key 或短期签名 CDN URL。

GUI 首版的 `app.py` 已集中窗口、表格和生命周期逻辑。新增队列/历史前可按下载页、账号页、设置页与任务控制器拆分，并保持单一事件边界。每个拆分都以现有交互/取消回归证明行为一致；无需先换 GUI 技术栈。

## 可测的优化目标

先测量 1.6.0 和候选在相同 VM/硬件上的冷/热启动（各至少 5 次）、空闲与下载峰值内存、100/1000 条模拟任务下界面响应，以及取消从请求到终态的耗时。记录磁盘、网络条件、平台会话和中位/最慢值。当前没有可靠性能基线，先采集再设门槛。

本地无网络等待的操作可先以 200 ms 内界面反馈、进度每秒约 5–10 次更新为设计目标；涉及请求等待的取消耗时单独记录，不能用固定 1 秒承诺掩盖超时边界。计划解析可缓存同批已取得的元数据，短期播放地址失效时重新解析；不跨权限状态复用未经验证的播放结果。

CLI 可优先完善 `config set/reset` 的校验与原子写入、离线诊断的 JSON 格式、批处理错误分类，以及 `info` 的选集/可用媒体展示。音频单独导出、字幕/封面等内容下载可在确认接口、权限和格式后另列需求，沿用当前授权与 DRM 边界。

## 下一版发布条件

沿用[持续测试规范](testing.md)和[验收模板](validation-template.md)，保留 1.6.0 原始文件作为升级基线。每个新能力同时更新 CLI/GUI 使用说明、帮助、用例 ID、版本记录和发行材料。新系统在原生构建/安装/可见桌面验证后才进入支持列表。

下一版应重点增加：旧稳定包→候选升级与低版行为、机器输出契约/脱敏、任务隔离/并发预算、历史迁移/中断恢复，以及更新源故障。没有实现的功能继续写为计划，不在首页或变更记录中提前宣称可用。
