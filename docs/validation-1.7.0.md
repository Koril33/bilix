### 实测缺陷与修复

1. curl-cffi 0.13.0 在 Linux 短流结束/Session 关闭阶段随机 Python abort，栈涉及 `curl_easy_reset` 与后台 cleanup。升级 0.16.3 后全量和三轮真实短流回归通过。依赖范围为 `>=0.16.3,<0.17`，uv.lock 只升级该依赖；没有修改安装后的依赖源码或跳过故障测试。新版独立流式句柄/关闭实现见[上游源码](https://github.com/lexiforest/curl_cffi/blob/v0.16.3/curl_cffi/requests/session.py)。
2. 真实 Windows Ctrl+Break 此前直接终止且留下临时目录；新增 SIGBREAK 协作处理并恢复原 handler。修复后退出 130，无输出/临时目录残留。
3. 尝试增加实际解析的 `resolved_ffmpeg`，区分快照的自动选择偏好和实际程序；详情区分媒体选择/FFmpeg/校验/合并错误。已存在文件跳过仍不要求 FFmpeg。
4. Linux 构建补齐 Nuitka 默认遗漏的 compose/IBus 插件和 Qt DBus 库，避免包含缺 Qt Quick 的虚拟键盘插件。插件加载与真实 IME 分别验收。
5. Inno BeforeInstall 异常可能被忽略，原故障注入不能证明回滚。改为写 runtime 后读取缺失 external 文件的实际 I/O 失败，验证旧完整目录/注册表恢复；正式包不定义 `ValidationFailure`。

## 性能与布局

生产窗口合成/offscreen 初轮五进程启动中位约 3196 ms、最慢 4811 ms（有构建/解码负载），空闲约 72 MiB。工具补齐排队取消/清理后五轮启动中位 605 ms、最慢 1017 ms，空闲 72.5–73.1 MiB，千项 78.3–78.8 MiB；1000 项终态反馈中位 2113 ms、最慢 4564 ms，清理中位 30 ms、最慢 44 ms，筛选/详情/单项重试为毫秒级。该同步合成事件指标不等于实际网络取消/桌面洪峰承诺。五轮数据保存在 `build/release-1.7.0/gui-perf-final-*`，不可只选择较快轮次报告。

800×600 基本/高级界面无横向截断，高级内容纵向滚动可达；这不代替原生 DPI/IME。最终冻结 onefile 与原 1.6.0 同主机各测 5 次初次组/5 次重复组自检，中位/最慢：1.6.0 初次 2802/3199 ms、重复 2827/3146 ms；1.7.0 初次 2796/2896 ms、重复 2664/2818 ms。记录 `frozen-perf-final/result.json` 绑定 exe 哈希。指标为自检退出墙钟时间，**不是首帧冷启动**；OS 缓存未清，bootstrap 内存不含 Qt 子进程。

打开约 18 分钟后的最终绿色版另采集一个原生空闲点：onefile 父进程 working set 37.8 MiB、Qt 子进程 128.6 MiB，合计约 166.4 MiB，记录 `frozen-native-idle.json`。各进程的独立峰值不能相加当作同时峰值；单点没有 1.6.0 原生窗口对照，不证明下载峰值。真实首帧、空闲对照/下载峰值及完整千项交互仍有验证缺口。
