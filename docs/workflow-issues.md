更新日期：2026-10-14（Asia/Shanghai）。基线为已发布 1.8.0 和当前仓库。本文跟踪全流程问题、验收缺口及接受的限制；未交付产品功能另见[需求登记](backlog.md)。本轮实现和检查的实际范围见[1.8.0 发行验收](validation-1.8.0.md)。

状态：**未做**为缺少完整流程/工具；**已实现待验证**为修改已经落地但验收尚未闭环；**接受限制**为已明确接受且公开说明的范围；**实际缺陷**为已有失败证据或用户报告，报告不等于根因已证实。P0 阻止受影响候选发布，P1 优先维护，P2 后续流程改进或补测，P3 可选。以下建议优先级不追溯否定已有版本的实际验收，也不自动扩大新版范围。

## WF-01 Windows 绿色版更新只下载、不替换、不重启

**状态：已在 1.7.9 发布。原优先级：P1；旧版需一次手动迁移。**

2026-10-13 用户报告 1.7.7 绿色版下载完成，点击更新后退出，却没有替换或重启。真实 Windows 系统调用回归确认：进程已退出、但启动器仍保留句柄时，`OpenProcess` 可以成功，`QueryFullProcessImageNameW` 却失败；旧逻辑误判为无法确认退出。此缺陷能够产生相同现象，但不能据此断言所有历史更新失败的根因都相同。[修复与迁移说明](portable-update-fix.md)

源码已改为先等待进程信号并处理查询期间退出竞态，同时补等待失败反馈、避免重复启动和 GUI 重试入口。新增真实 Windows 用例修复前 5 失败/3 通过、修复后 8 通过；更新与 GUI 专项共 **60 通过**。Windows 10 build 19045 普通交互会话已通过受控离线同版本测试 onefile → 生产 1.7.9：非空两个父/子 PID、自身复制外部协调器、保留已退出进程句柄、中文改名的原路径替换、旧 EXE 备份、新启动确认及用户数据守恒。该结果不宣称旧版协调器已被修复，也不等同于自然公开升级；最终回归及候选状态见[1.7.9 验收记录](validation-1.7.9.md)。

证据边界：[1.7.8 记录](validation-1.7.8.md#界面规模与平台包)有 1.7.7 → 1.7.8 的 Windows 实际更新事务通过；其[公开渠道回验](validation-1.7.8.md#发行材料安全与渠道)中的 `live-client-verification.json` 只执行下载和校验，明确没有安装调用。历史成功和公开下载成功均不能排除本次用户环境的失败。

**完成/验收标准：**修复后的冻结绿色程序，经生产 GUI 和真实 `handoff()`、非空 onefile 父/子进程记录、真正退出、外部协调器、原路径替换、新普通用户窗口及 `startup.json/result.json` 确认，完整留证；验证非默认偏好和已有下载保留，失败错误可见且受控恢复。受控签名事务与公开网络发现分开验收。用户已选择旧版一次手动迁移；旧版把自身复制为协调器，下载的新包不能追溯修正旧逻辑，因此 **1.7.7 自然自动升级到 1.7.9 不作为本次修复能够保证的验收承诺**。已发布 v1.7.8 和公开文件保持不可变，修复产物使用新版本。

**后续依赖：**[updates.py](../src/djhx_bilix/gui/updates.py)、[apply.py](../src/djhx_bilix/updater/apply.py)、[processes.py](../src/djhx_bilix/updater/processes.py)、修复后的冻结候选与专用 VM；须同步 WF-02 的完整交接覆盖。日志只公开安全阶段/结果/版本/哈希，不公开凭据或用户原始路径。

## 已闭环事项与关闭规则

官网首页和站点根目录权限已于 2026-10-12 授予 `bilix:bilix`，并由 [deploy_site.py](../scripts/deploy_site.py)原子部署、备份及 HTTPS 全页核对；不再登记“等待管理员密码/首页权限”。发行文件、签名更新、APT 和官网统一使用 **`bilix@djhx.site`**，管理员只维护 TLS/Nginx/系统服务及权限恢复。Gitea 只同步代码/标签，未提供安装资产镜像是当前渠道定位，不是本轮未完成镜像发布。Windows 代码签名证书已决定不购买，不列欠项。

已修复的产品问题、已补齐的 GNOME/KDE Wayland、Linux 授权更新和各渠道 1.7.8 全量回读沿用版本记录，不重新列开放缺陷。关闭一项须添加实际实现/文档提交、测试环境和结果、受影响产物哈希及证据位置；“计划完成”“脚本通过”或“下载成功”不能直接关闭完整更新/发布事务。真实密码、私钥内容、Cookie/token、二维码及原始账号日志不进入本文件或公开归档。
